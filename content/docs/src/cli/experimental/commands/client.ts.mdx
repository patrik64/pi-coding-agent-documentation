`pi experimental client` connects to a running server and opens a session. This file does not connect to anything. It declares the options, validates their combination, and produces a plain `ClientCommand` object, then hands it to `context.runClient`. This is experimental code.

It is built from [command.ts](/docs/src/cli/experimental/command.ts) and the shared options in [command-options.ts](/docs/src/cli/experimental/command-options.ts), registered by [cli.ts](/docs/src/cli/experimental/cli.ts), and its sibling is [server.ts](/docs/src/cli/experimental/commands/server.ts). The runtime side is in [client.ts](/docs/src/experimental/client.ts).

<Scrollycoding>

## !!steps The invocation and its context

`ClientCommand` lists everything a client run can be told: auth, a connect address, session selection, model selection, plugin packages and an initial prompt. The context interface is the single side effect the command needs.

```ts ! client.ts
export interface ClientCommand {
	readonly command: "client";
	readonly auth?: AuthInput;
	readonly connect?: TransportAddress;
	readonly sessionId?: string;
	readonly continue?: boolean;
	readonly resume?: boolean;
	readonly provider?: string;
	readonly model?: string;
	readonly pluginPackages?: readonly string[];
	readonly prompt?: string;
}

export interface ClientCommandContext {
	runClient(command: ClientCommand): void | Promise<void>;
}
```

## !!steps Declaring options

Short and long forms are separate options, so `-c` and `--continue` are registered twice and merged later. `-e` is repeatable to load several plugin packages.

```ts ! client.ts
const sessionIdOption = stringOption("--session-id");
const continueOption = flagOption("--continue");
const continueShortOption = flagOption("-c");
const resumeOption = flagOption("--resume");
const resumeShortOption = flagOption("-r");
const providerOption = stringOption("--provider");
const modelOption = stringOption("--model");
// !mark
const pluginPackageOption = stringOption("-e", { repeatable: true });
```

## !!steps Extracting the prompt

The prompt is whatever single positional argument remains. After an optional leading `--`, exactly one non-empty argument qualifies; without `--` it must not begin with a dash. Anything else leaves `prompt` undefined and falls through to the unsupported-options error.

```ts ! client.ts
		const promptArgs = input.remainingArgs[0] === "--" ? input.remainingArgs.slice(1) : input.remainingArgs;
		// !mark(1:5)
		const prompt =
			promptArgs.length === 1 &&
			(input.remainingArgs[0] === "--" || !promptArgs[0]!.startsWith("-")) &&
			promptArgs[0]!.length > 0
				? promptArgs[0]
				: undefined;
```

## !!steps Cross-option validation

Providers need a model, and at most one of session id, continue or resume may be set. Errors from auth parsing and from leftover arguments are collected together, so one failed run reports everything.

```ts ! client.ts
		const modelErrors = provider !== undefined && model === undefined ? ["--provider requires --model"] : [];
		const sessionSelectionErrors =
			[sessionId !== undefined, shouldContinue, shouldResume].filter(Boolean).length > 1
				? ["--session-id, --continue, and --resume are mutually exclusive"]
				: [];
		const unsupportedErrors =
			input.remainingArgs.length === 0 || prompt !== undefined ? [] : unsupportedOptions("client", input);
		const errors = [...authErrors, ...modelErrors, ...sessionSelectionErrors, ...unsupportedErrors];
		if (errors.length > 0) return { ok: false, errors };
```

## !!steps A sparse command and the action

The result spreads each field only when set, which keeps `undefined` keys out of the object under strict optional typing. The action simply forwards the command to the host context.

```ts ! client.ts
				...(shouldContinue ? { continue: true } : {}),
				...(shouldResume ? { resume: true } : {}),
				...(provider === undefined ? {} : { provider }),
				...(model === undefined ? {} : { model }),
				...(pluginPackages.length === 0 ? {} : { pluginPackages }),
				...(prompt === undefined ? {} : { prompt }),
			},
		};
	})
	// !mark
	.action((command, context) => context.runClient(command));
```

</Scrollycoding>

The command never touches the network itself, which keeps it easy to test: parsing is a pure function from argv to a result.
