`pi auth check` answers one question for scripts and CI: is this provider ready to be used? This file turns the parsed CLI arguments into a small structured result (`ready`, `not_ready` or `invalid`, with a machine-readable reason) rather than throwing for ordinary "not configured" cases.

It sits on top of [model-runtime.ts](/docs/src/core/model-runtime.ts) for provider and credential lookups, [model-resolver.ts](/docs/src/core/model-resolver.ts) for turning `--model` into a provider, and [auth-command.ts](/docs/src/cli/auth-command.ts) for argument validation. The sibling [credential-print.ts](/docs/src/cli/credential-print.ts) handles the commands that actually emit secrets.

## !!steps The result shape

Three statuses and four reasons form a closed vocabulary that a `--json` consumer can switch on. `authType` is only present when the check succeeded.

```ts ! auth-check.ts
export type AuthCheckStatus = "ready" | "not_ready" | "invalid";
export type AuthCheckReason =
	| "provider_not_found"
	| "credentials_not_configured"
	| "credential_not_available"
	| "invalid_state";

export interface AuthCheckResult {
	status: AuthCheckStatus;
	provider: string;
	reason?: AuthCheckReason;
	authType?: "api_key" | "oauth";
}
```

## !!steps Resolving which provider to check

Arguments are validated first. If `--model` was given, it is resolved through the model resolver and the provider is taken from the resolved model, overriding `--provider`. Resolution problems and a missing provider are thrown as `AuthCommandError`, which the caller reports as a usage error rather than a check result.

```ts ! auth-check.ts
export async function checkProviderAuth(
	args: Args,
	modelRuntime: ModelRuntime,
	options: { refresh: boolean } = { refresh: false },
): Promise<AuthCheckResult> {
	// !mark
	const { provider: cliProvider, model: cliModel } = validateAuthCommandArgs(args, "check");
	let provider = cliProvider;
	if (cliModel) {
		const resolved = resolveCliModel({ cliProvider, cliModel, modelRuntime });
		if (resolved.error || !resolved.model) {
			throw new AuthCommandError(resolved.error ?? `Unable to resolve model "${cliModel}"`);
		}
		provider = resolved.model.provider;
	}
	if (!provider) throw new AuthCommandError("Unable to resolve an auth provider");
```

## !!steps Classifying the outcome

A runtime that failed to load its configuration reports `invalid_state`; an unknown provider is `not_ready`. Then `checkAuth` is consulted. With `refresh` enabled, it additionally calls `getAuth`, which can refresh expired OAuth credentials, and treats a failure to obtain auth as not configured. Any thrown error collapses to `invalid_state`.

```ts ! auth-check.ts
	if (modelRuntime.getError()) {
		return { status: "invalid", provider, reason: "invalid_state" };
	}
	if (!modelRuntime.getProvider(provider)) {
		return { status: "not_ready", provider, reason: "provider_not_found" };
	}
	try {
		const auth = await modelRuntime.checkAuth(provider);
		if (!auth) return { status: "not_ready", provider, reason: "credentials_not_configured" };
		// !mark(1:3)
		if (options.refresh && !(await modelRuntime.getAuth(provider))) {
			return { status: "not_ready", provider, reason: "credentials_not_configured" };
		}
		return { status: "ready", provider, authType: auth.type };
	} catch {
		return { status: "invalid", provider, reason: "invalid_state" };
	}
}
```

## !!steps Fetching the credential for output

When `--credentials` is requested, this helper returns the secret. Without `refresh`, a stored OAuth credential's access token is returned directly, with no network call; otherwise the value comes from `getAuth`, which may refresh and persist a new token.

```ts ! auth-check.ts
export async function getProviderCredential(
	providerId: string,
	modelRuntime: ModelRuntime,
	credentials: CredentialStore,
	options: { refresh: boolean },
): Promise<string | undefined> {
	const credential = await credentials.read(providerId);
	// !mark
	if (!options.refresh && credential?.type === "oauth") return credential.access;
	return getAuthCredential(await modelRuntime.getAuth(providerId));
}
```

## !!steps A deliberately offline runtime

The check command builds its own `ModelRuntime` with an in-memory models store, no model network access and no refresh on creation. That keeps `auth check` fast and side-effect free; see [models-store.ts](/docs/src/core/models-store.ts) for the in-memory store.

```ts ! auth-check.ts
export async function createAuthCheckModelRuntime(credentials: CredentialStore): Promise<ModelRuntime> {
	return ModelRuntime.create({
		credentials,
		modelsStore: new InMemoryCodingAgentModelsStore(),
		// !mark(1:2)
		allowModelNetwork: false,
		refreshOnCreate: false,
	});
}
```
