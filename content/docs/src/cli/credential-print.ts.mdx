These commands exist so shell scripts can ask pi for a credential, for example to call a provider API directly. The function here must return exactly one secret or fail with a clear message, because printing the wrong one, or an arbitrary one of several, would be worse than an error.

It validates arguments via [auth-command.ts](/docs/src/cli/auth-command.ts), resolves models with [model-resolver.ts](/docs/src/core/model-resolver.ts), and gets credentials through [model-runtime.ts](/docs/src/core/model-runtime.ts), which handles OAuth refresh. The read-only counterpart is [auth-check.ts](/docs/src/cli/auth-check.ts).

<Scrollycoding>

## !!steps Refresh is intentional

The doc comment makes a point: this path calls `getAuth`, which refreshes and persists OAuth credentials that have under five minutes left. The default minimum validity for bearer tokens is 30 minutes, so a printed token should stay usable for a while.

```ts ! credential-print.ts
const DEFAULT_BEARER_TOKEN_MIN_EXPIRY_MS = 30 * 60_000;

type CredentialPrintKind = Exclude<AuthCommandKind, "check">;

/**
 * Resolve one configured provider credential.
 *
 * This intentionally calls ModelRuntime.getAuth(), which refreshes and persists
 * OAuth credentials with less than five minutes remaining through the normal request-auth path.
 */
```

## !!steps Candidate providers from an explicit provider

First the credential types on disk are listed into a map. With `--provider`, an unknown provider is an error; with `--model` also given, the model is resolved inside that provider and kept so auth can be fetched for the specific model.

```ts ! credential-print.ts
	const credentialTypes = new Map<string, CredentialInfo["type"]>(
		(await modelRuntime.listCredentials({ signal })).map((credential) => [credential.providerId, credential.type]),
	);
	const providers: Array<{ id: string; model?: Model<Api> }> = [];
	// !mark
	if (cliProvider) {
		const provider = modelRuntime.getProvider(cliProvider);
		if (!provider) {
			throw new AuthCommandError(`Unknown provider "${cliProvider}". Use --list-models to see available providers.`);
		}
```

## !!steps Candidate providers from a model alone

Without `--provider`, every provider that has a stored credential is tried against the model name. Custom model ids (resolver warning "Using custom model id") are excluded, so only genuinely known models match. If none match, the error says the model was not found.

```ts ! credential-print.ts
		for (const provider of modelRuntime.getProviders()) {
			if (!credentialTypes.has(provider.id)) continue;
			const resolved = resolveCliModel({ cliProvider: provider.id, cliModel: cliModel!, modelRuntime });
			// !mark
			if (resolved.model && !resolved.error && !resolved.warning?.includes("Using custom model id")) {
				providers.push({ id: provider.id, model: resolved.model });
			}
		}
```

## !!steps Filtering by credential kind

API-key printing skips OAuth providers and bearer printing skips non-OAuth ones. Only bearer requests pass `minOAuthValidityMs`. A model-specific request calls `getAuth` with the model, otherwise with the provider id.

```ts ! credential-print.ts
	for (const provider of providers) {
		const type = credentialTypes.get(provider.id);
		// !mark(1:2)
		if (kind === "api_key" && type === "oauth") continue;
		if (kind === "bearer_token" && type !== "oauth") continue;
		const authOptions = {
			...(kind === "bearer_token" ? { minOAuthValidityMs: minExpiryMs ?? DEFAULT_BEARER_TOKEN_MIN_EXPIRY_MS } : {}),
			signal,
		};
		const auth = provider.model
			? await modelRuntime.getAuth(provider.model, authOptions)
			: await modelRuntime.getAuth(provider.id, authOptions);
		const value = getAuthCredential(auth);
		if (value) credentials.push({ providerId: provider.id, value });
	}
```

## !!steps Exactly one, or a precise error

One match is returned. Zero matches produce a message that depends on why: an OAuth provider asked for an API key, a non-OAuth provider asked for a bearer token, or simply nothing usable. More than one match is ambiguous and lists the providers so the user can add `--provider`.

```ts ! credential-print.ts
	if (credentials.length === 1) return credentials[0].value;
	if (credentials.length === 0) {
		const providerId = providers[0]?.id;
		const type = providerId ? credentialTypes.get(providerId) : undefined;
		if (cliProvider && kind === "api_key" && type === "oauth") {
			throw new AuthCommandError(`Provider "${providerId}" is configured with OAuth, not an API key`);
		}
		// !mark
		throw new AuthCommandError(`No usable ${kind === "api_key" ? "API key" : "OAuth bearer token"} is configured`);
	}
	throw new AuthCommandError(
		`Multiple configured providers matched (${credentials.map(({ providerId }) => providerId).join(", ")}). Specify --provider.`,
	);
```
