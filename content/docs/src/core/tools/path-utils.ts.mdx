The model types paths from text, and users paste them from a terminal or a
screenshot. On macOS the file the user means often has a slightly different
name than the string they typed: screenshot names contain a narrow no-break
space before AM or PM, accented names are stored in decomposed Unicode form, and
apostrophes in some locales are curly. This file resolves a path against the
cwd and, for reads, tries those variants when the literal path does not exist.

It builds on the generic helpers in [paths.ts](/docs/src/utils/paths.ts) and is
used by [read.ts](/docs/src/core/tools/read.ts),
[write.ts](/docs/src/core/tools/write.ts), [edit.ts](/docs/src/core/tools/edit.ts),
[ls.ts](/docs/src/core/tools/ls.ts), [find.ts](/docs/src/core/tools/find.ts) and
[grep.ts](/docs/src/core/tools/grep.ts).

## !!steps Three name transformations

Each helper produces one candidate spelling. The AM/PM rewrite replaces the
space before `AM.` or `PM.` with U+202F, which macOS uses in screenshot names.
The NFD variant normalizes to decomposed form because that is how macOS stores
names. The curly-quote variant swaps every straight apostrophe for U+2019.

```ts ! path-utils.ts
const NARROW_NO_BREAK_SPACE = "\u202F";

function tryMacOSScreenshotPath(filePath: string): string {
	return filePath.replace(/ (AM|PM)\./gi, `${NARROW_NO_BREAK_SPACE}$1.`);
}

function tryNFDVariant(filePath: string): string {
	// macOS stores filenames in NFD (decomposed) form, try converting user input to NFD
	return filePath.normalize("NFD");
}

function tryCurlyQuoteVariant(filePath: string): string {
	// macOS uses U+2019 (right single quotation mark) in screenshot names like "Capture d'écran"
	// Users typically type U+0027 (straight apostrophe)
	return filePath.replace(/'/g, "\u2019");
}
```

## !!steps Existence checks and plain resolution

There is a sync and an async existence check, both using `F_OK`. `expandPath` and
`resolveToCwd` both delegate to `normalizePath` and `resolvePath`, with
`normalizeUnicodeSpaces` and `stripAtPrefix` on. Stripping a leading `@` tolerates
paths written with an `@` prefix, as in file mentions.

```ts ! path-utils.ts
export async function pathExists(filePath: string): Promise<boolean> {
	try {
		await access(filePath, constants.F_OK);
		return true;
	} catch {
		return false;
	}
}

export function expandPath(filePath: string): string {
	return normalizePath(filePath, { normalizeUnicodeSpaces: true, stripAtPrefix: true });
}

/**
 * Resolve a path relative to the given cwd.
 * Handles ~ expansion and absolute paths.
 */
export function resolveToCwd(filePath: string, cwd: string): string {
	return resolvePath(filePath, cwd, { normalizeUnicodeSpaces: true, stripAtPrefix: true });
}
```

## !!steps Trying variants in order for reads

`resolveReadPath` resolves first, then returns the literal path if it exists.
Otherwise it tries AM/PM, NFD and curly quote one after another and returns the
first that exists. Each attempt is skipped when the transformation changed
nothing. If nothing matches, it returns the original resolved path, so the
caller's later read produces the normal not-found error.

```ts ! path-utils.ts
export function resolveReadPath(filePath: string, cwd: string): string {
	const resolved = resolveToCwd(filePath, cwd);

	if (fileExists(resolved)) {
		return resolved;
	}

	// Try macOS AM/PM variant (narrow no-break space before AM/PM)
	const amPmVariant = tryMacOSScreenshotPath(resolved);
	if (amPmVariant !== resolved && fileExists(amPmVariant)) {
		return amPmVariant;
	}

	// Try NFD variant (macOS stores filenames in NFD form)
	const nfdVariant = tryNFDVariant(resolved);
	if (nfdVariant !== resolved && fileExists(nfdVariant)) {
		return nfdVariant;
	}
```

## !!steps The combined variant and the async twin

The last attempt combines NFD with curly quotes, for names like a French
"Capture d'ecran" screenshot that need both. The `resolveReadPathAsync` function
repeats the same ladder with `await pathExists`, so the read tool can avoid
blocking the event loop.

```ts ! path-utils.ts
	// Try combined NFD + curly quote (for French macOS screenshots like "Capture d'écran")
	const nfdCurlyVariant = tryCurlyQuoteVariant(nfdVariant);
	if (nfdCurlyVariant !== resolved && fileExists(nfdCurlyVariant)) {
		return nfdCurlyVariant;
	}

	return resolved;
}

export async function resolveReadPathAsync(filePath: string, cwd: string): Promise<string> {
	const resolved = resolveToCwd(filePath, cwd);

	if (await pathExists(resolved)) {
		return resolved;
	}
```

</Scrollycoding>

Only reads use the variant search; writes and edits use `resolveToCwd` so a
new file is created exactly where requested. The sync and async ladders are
copies of each other and must be kept in step by hand. Within the source tree,
the sync `resolveReadPath` is called only by
[file-processor.ts](/docs/src/cli/file-processor.ts), and `expandPath` appears
to have no callers.
