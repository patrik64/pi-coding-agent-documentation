The write tool's call arguments contain the entire file content, and the model streams them token by token. This renderer shows that content live under the header, syntax-highlighted by language. Re-highlighting a growing file from scratch on every token would be quadratic, so the file is mostly about a cache that updates only the part that changed. Once the arguments are complete, the whole file is highlighted once and the result is reused across redraws and expand toggles.

The tool implementation is [tools/write.ts](/docs/src/core/tools/write.ts); renderers live apart so a presentation process avoids loading it. Highlighting comes from [theme.ts](/docs/src/modes/interactive/theme/theme.ts), and path and text helpers from [render-utils.ts](/docs/src/core/tools/render-utils.ts).

## !!steps The highlight cache and call component

The cache remembers the raw content it was built from, the same content with tabs and carriage returns normalized, and the highlighted version of each line. `WriteCallRenderComponent` is a `Text` that carries one cache between renders, used only while the content is still streaming.

It also owns a `CodeHighlighter` from [theme.ts](/docs/src/modes/interactive/theme/theme.ts), which remembers its last input and output and returns the previous lines when the code, language, theme and set of loaded grammars are all unchanged. The renderer cannot tell a theme change from any other redraw, so the highlighter checks those itself. For a complete call it holds the only copy of the highlighted source.

```ts ! write.ts
type WriteHighlightCache = {
	rawPath: string | null;
	lang: string;
	rawContent: string;
	normalizedLines: string[];
	highlightedLines: string[];
};
class WriteCallRenderComponent extends Text {
	// Line by line highlighting of a call whose content is still streaming.
	cache?: WriteHighlightCache;
	// A streamed call highlights its first lines on every delta, which stop changing once the file is longer, and a
	// complete call highlights the whole file on every update and expand toggle. Either way the row reuses the last
	// highlighting; it also holds the only copy of a complete call's displayed source.
	readonly highlighter = new CodeHighlighter();

	constructor() {
		super("", 0, 0);
	}
}
```

## !!steps Full rebuild

`rebuildWriteHighlightCacheFull` is the slow path, used when streaming starts or the cache cannot be extended. It returns `undefined` when the path has no known language, which makes callers fall back to plain text. Otherwise it normalizes the content and highlights it as one block.

```ts ! write.ts
function rebuildWriteHighlightCacheFull(rawPath: string | null, fileContent: string): WriteHighlightCache | undefined {
	const lang = rawPath ? getLanguageFromPath(rawPath) : undefined;
	// !mark
	if (!lang) return undefined;
	const displayContent = normalizeDisplayText(fileContent);
	const normalized = replaceTabs(displayContent);
	return {
		rawPath,
		lang,
		rawContent: fileContent,
		normalizedLines: normalized.split("\n"),
		highlightedLines: highlightCode(normalized, lang),
	};
}
```

## !!steps Incremental update

While content streams, each render passes the longer string. The function validates that the cache still applies: same language and path, and the new content must start with the cached raw content (otherwise the model rewrote earlier text). If the length is unchanged it returns the cache as is.

Otherwise only the appended delta is processed. Its first segment extends the current last line, which is re-highlighted alone; each further segment becomes a new line, highlighted individually.

```ts ! write.ts
function updateWriteHighlightCacheIncremental(
	cache: WriteHighlightCache | undefined,
	rawPath: string | null,
	fileContent: string,
	highlighter: CodeHighlighter,
): WriteHighlightCache | undefined {
	const lang = rawPath ? getLanguageFromPath(rawPath) : undefined;
	if (!lang) return undefined;
	if (!cache) return rebuildWriteHighlightCacheFull(rawPath, fileContent);
	// !mark(1:4)
	if (cache.lang !== lang || cache.rawPath !== rawPath || !fileContent.startsWith(cache.rawContent)) {
		return rebuildWriteHighlightCacheFull(rawPath, fileContent);
	}
	if (fileContent.length === cache.rawContent.length) return cache;
// ...
	const segments = deltaNormalized.split("\n");
	const lastIndex = cache.normalizedLines.length - 1;
	cache.normalizedLines[lastIndex] += segments[0];
	cache.highlightedLines[lastIndex] = highlightSingleLine(cache.normalizedLines[lastIndex], cache.lang);
	for (let i = 1; i < segments.length; i++) {
		cache.normalizedLines.push(segments[i]);
		cache.highlightedLines.push(highlightSingleLine(segments[i], cache.lang));
	}
	refreshWriteHighlightPrefix(cache, highlighter);
	return cache;
}
```

## !!steps Re-highlighting the visible prefix

Line-by-line highlighting loses multi-line context, such as an open block comment or template string. The part the user is looking at is the top of the file, so after each update the first 50 lines are highlighted together as a block and written back over the cached lines. The block goes through the component's `CodeHighlighter`: once the file is longer than 50 lines the prefix stops changing, and each further delta reuses the previous highlighting instead of redoing it. Lines beyond the prefix keep the cheap single-line highlight until the arguments complete.

```ts ! write.ts
const WRITE_PARTIAL_FULL_HIGHLIGHT_LINES = 50;
function highlightSingleLine(line: string, lang: string): string {
	const highlighted = highlightCode(line, lang);
	return highlighted[0] ?? "";
}
function refreshWriteHighlightPrefix(cache: WriteHighlightCache, highlighter: CodeHighlighter): void {
	const prefixCount = Math.min(WRITE_PARTIAL_FULL_HIGHLIGHT_LINES, cache.normalizedLines.length);
	if (prefixCount === 0) return;
	// !mark(1:5)
	const prefixSource = cache.normalizedLines.slice(0, prefixCount).join("\n");
	const prefixHighlighted = highlighter.highlight(prefixSource, cache.lang);
	for (let i = 0; i < prefixCount; i++) {
		cache.highlightedLines[i] =
			prefixHighlighted[i] ?? highlightSingleLine(cache.normalizedLines[i] ?? "", cache.lang);
	}
}
```

## !!steps Formatting the call

The header is `write <path>`. An invalid content argument shows an error line. Otherwise content is shown from the streaming cache when there is one, or highlighted as a whole by the component's `CodeHighlighter`, or split raw for unknown languages. Collapsed shows ten lines and a hint that includes the total line count; expanded shows all. Because the highlighter returns its last result for identical input, toggling expansion on a finished call does not re-highlight the file.

```ts ! write.ts
	if (fileContent === null) {
		text += `\n\n${theme.fg("error", "[invalid content arg - expected string]")}`;
	} else if (fileContent) {
		const lang = rawPath ? getLanguageFromPath(rawPath) : undefined;
		const renderedLines = lang
			// !mark
			? (cache?.highlightedLines ?? highlighter.highlight(replaceTabs(normalizeDisplayText(fileContent)), lang))
			: normalizeDisplayText(fileContent).split("\n");
		const lines = trimTrailingEmptyLines(renderedLines);
		const totalLines = lines.length;
		const maxLines = options.expanded ? lines.length : 10;
		const displayLines = lines.slice(0, maxLines);
		const remaining = lines.length - maxLines;
		text += `\n\n${displayLines.map((line) => (lang ? line : theme.fg("toolOutput", replaceTabs(line)))).join("\n")}`;
```

## !!steps Streaming cache or whole-file highlight, and the result

`renderCall` keeps the incremental cache only while `context.argsComplete` is false. Once the arguments are final, or when the content is not a string, the cache is dropped, and the formatter highlights the full text through the `CodeHighlighter`, so the finished view has exact multi-line highlighting computed once.

`renderResult` is nearly empty on success: it returns an empty container, because the call component already shows the content. Only an error produces text, in red.

```ts ! write.ts
		const component =
			(context.lastComponent as WriteCallRenderComponent | undefined) ?? new WriteCallRenderComponent();
		// !mark(1:4)
		component.cache =
			fileContent !== null && !context.argsComplete
				? updateWriteHighlightCacheIncremental(component.cache, rawPath, fileContent, component.highlighter)
				: undefined;
		component.setText(
			formatWriteCall(
				renderArgs,
				{ expanded: context.expanded, isPartial: context.isPartial },
				theme,
				component.cache,
				component.highlighter,
				context.cwd,
			),
		);
```

The pair is registered by [renderers/index.ts](/docs/src/core/tools/renderers/index.ts) and typed through [extensions/types.ts](/docs/src/core/extensions/types.ts). Structurally, this is the only renderer besides [renderers/edit.ts](/docs/src/core/tools/renderers/edit.ts) that keeps mutable state on its component, and both use it to avoid repeating expensive work as arguments stream. A duplicated helper: `trimTrailingEmptyLines` is defined identically here and in [renderers/read.ts](/docs/src/core/tools/renderers/read.ts).
