This is the whole front end of an exported session, in one self-invoking function. [index.ts](/docs/src/core/export-html/index.ts) inlines it into [template.html](/docs/src/core/export-html/template.html) together with the session data, so the exported file is a standalone viewer with no server.

It does four jobs: decode the embedded entries, turn the flat list into a tree of branches, render the chosen path as HTML strings, and wire up interaction (search, filters, resizable sidebar, keyboard shortcuts, deep links). Entries follow the structure written by [session-manager.ts](/docs/src/core/session-manager.ts), where each has an id and a parent id, so a session with several branches is a tree and the page shows one root-to-leaf path at a time.

## !!steps Decoding the embedded session

The data element holds base64, not JSON. It is decoded to bytes and then through `TextDecoder` as UTF-8, because plain `atob` yields a Latin-1 string and would corrupt non-ASCII text. The decoded object carries the header, the entries, a default leaf id, the system prompt, tool definitions, and `renderedTools`, the HTML produced by [tool-renderer.ts](/docs/src/core/export-html/tool-renderer.ts).

```js ! template.js
      const base64 = document.getElementById('session-data').textContent;
      const binary = atob(base64);
      const bytes = new Uint8Array(binary.length);
      for (let i = 0; i < binary.length; i++) {
        bytes[i] = binary.charCodeAt(i);
      }
      const data = JSON.parse(new TextDecoder('utf-8').decode(bytes));
      const { header, entries, leafId: defaultLeafId, systemPrompt, tools, renderedTools } = data;
```

## !!steps Deep links choose the branch

Two query parameters control the view: `leafId` selects which branch to display and `targetId` selects the message to scroll to. When the page is loaded in an iframe via `srcdoc`, there is no real query string, so a `pi-url-params` meta element carries the parameters instead. Without a `leafId`, the session's own default leaf is used.

```js ! template.js
      // Parse URL parameters for deep linking: leafId and targetId
      // Check for injected params (when loaded in iframe via srcdoc) or use window.location
      const injectedParams = document.querySelector('meta[name="pi-url-params"]');
      const searchString = injectedParams ? injectedParams.content : window.location.search.substring(1);
      const urlParams = new URLSearchParams(searchString);
      const urlLeafId = urlParams.get('leafId');
      const urlTargetId = urlParams.get('targetId');
      // Use URL leafId if provided, otherwise fall back to session default
      const leafId = urlLeafId || defaultLeafId;
```

## !!steps From a flat list to a tree

Each entry becomes a node, then is attached to the node of its `parentId`. A missing parent, a self-parent, or a null parent all make the node a root, so a session with a pruned or damaged history still renders. Children are sorted by timestamp so older branches appear first.

```js ! template.js
        // Build parent-child relationships
        for (const entry of entries) {
          const node = nodeMap.get(entry.id);
          if (entry.parentId === null || entry.parentId === undefined || entry.parentId === entry.id) {
            roots.push(node);
          } else {
            const parent = nodeMap.get(entry.parentId);
            if (parent) {
              parent.children.push(node);
            } else {
              roots.push(node);
            }
          }
        }

        // Sort children by timestamp
        function sortChildren(node) {
          node.children.sort((a, b) =>
            new Date(a.entry.timestamp).getTime() - new Date(b.entry.timestamp).getTime()
          );
          node.children.forEach(sortChildren);
        }
        roots.forEach(sortChildren);

        return roots;
      }
```

## !!steps Filtering the tree

The sidebar filter always keeps the current leaf visible. Assistant messages that contain only tool calls are hidden unless they ended in an error or abort. The settings-like entry types (label, custom, context edit, model change, thinking level change) are what the default and no-tools modes drop, and search requires every whitespace-separated token to appear in the entry text. Afterwards the visual structure is recomputed so hidden entries do not leave gaps in the indentation.

```js ! template.js
          const label = flatNode.node.label;
          const isCurrentLeaf = entry.id === currentLeafId;

          // Always show current leaf
          if (isCurrentLeaf) return true;

          // Hide assistant messages with only tool calls (no text) unless error/aborted
          if (entry.type === 'message' && entry.message.role === 'assistant') {
            const msg = entry.message;
            const hasText = hasTextContent(msg.content);
```

## !!steps Escaping and URL safety

All dynamic strings go through `escapeHtml` because the page builds HTML by string concatenation. Markdown links additionally pass a scheme allow-list (http, https, mailto, tel, ftp) after control characters are stripped, since browsers ignore such characters inside schemes and `java\tscript:` style tricks would otherwise slip through.

```js ! template.js
      function escapeHtml(text) {
        return String(text)
          .replace(/&/g, '&amp;')
          .replace(/</g, '&lt;')
          .replace(/>/g, '&gt;')
          .replace(/"/g, '&quot;')
          .replace(/'/g, '&#39;');
      }

      function sanitizeMarkdownUrl(value) {
        const href = String(value || '').trim().replace(/[\x00-\x1f\x7f]/g, '');
        if (!href) return href;

        const scheme = href.match(/^([A-Za-z][A-Za-z0-9+.-]*):/);
        if (scheme && !/^(https?|mailto|tel|ftp)$/i.test(scheme[1])) {
          return null;
        }

        return href;
      }
```

## !!steps Sidebar width and the mobile drawer

Width is clamped between a minimum and a maximum that leaves at least 320px for content, and stored in `localStorage` under a versioned key. Every storage access is wrapped in a try and catch, so private browsing modes simply lose persistence. The mobile layout uses the same 900px breakpoint as the stylesheet.

```js ! template.js
      const SIDEBAR_WIDTH_STORAGE_KEY = 'pi-share:v1:sidebar-width';
      const MIN_CONTENT_WIDTH = 320;

      function isMobileLayout() {
        return window.matchMedia('(max-width: 900px)').matches;
      }

      function getSidebarBounds() {
        const rootStyles = getComputedStyle(document.documentElement);
        const minWidth = parseFloat(rootStyles.getPropertyValue('--sidebar-min-width')) || 240;
        const maxWidth = parseFloat(rootStyles.getPropertyValue('--sidebar-max-width')) || 720;
        const viewportMaxWidth = window.innerWidth - MIN_CONTENT_WIDTH;
        return {
          minWidth,
          maxWidth: Math.max(minWidth, Math.min(maxWidth, viewportMaxWidth))
        };
      }

      function clampSidebarWidth(width) {
        const { minWidth, maxWidth } = getSidebarBounds();
        return Math.max(minWidth, Math.min(maxWidth, width));
      }

      function applySidebarWidth(width) {
        document.documentElement.style.setProperty('--sidebar-width', `${Math.round(clampSidebarWidth(width))}px`);
      }
```

## !!steps Keyboard shortcuts and first render

Escape clears the search and returns to the leaf. The letters t, o and h toggle thinking, tool output and hidden messages, but only when no modifier is held and focus is not in an input, textarea, select or button. The last lines choose the initial view: deep link target, default leaf, or the final entry.

The file depends on the names produced by the exporter in [index.ts](/docs/src/core/export-html/index.ts), in particular the `renderedTools` map and the entry shapes, and on the classes in [template.css](/docs/src/core/export-html/template.css). Structurally, nearly everything is a function inside one closure sharing mutable state such as the current leaf, search query and filter mode.
