This is the engine behind the codemode tool. [tool.ts](/docs/src/extensions/codemode/tool.ts) describes the tool to the model; this file takes the model's script, waits for a free sandbox worker, builds a `CodemodeSandbox` from the `pi-codemode` package, wires the sandbox to the session's tools, runs it, and turns the outcome into a tool result.

It is loaded lazily through [execute.lazy.ts](/docs/src/extensions/codemode/execute.lazy.ts). Most of the file is defensive input checking and bookkeeping, so that mistakes in a script produce messages that say what shape was expected. Since the version first documented here it has gained a worker queue shared by every session in the process, and a layout step that keeps separate output items distinguishable to the model.

## !!steps Limits and the model call limiter

Two limits protect the host. At most four `models.classify()` and `models.generateImages()` calls run at once per script, and the QuickJS heap is capped at 256 MiB. The worker shares pi's process, so without a cap a runaway script could grow towards the 4 GiB wasm limit and take the session down; overruns throw `InternalError: out of memory` inside the script.

`createLimiter` is a small queue: calls wait in order when the limit is reached, and each finished call wakes the next.

```ts ! execute.ts
/** `models.classify()` and `models.generateImages()` calls one script may have in flight; `Promise.all` over many items queues the rest. */
const MAX_CONCURRENT_MODEL_CALLS = 4;
/**
 * Heap limit for the QuickJS VM. The worker shares pi's process, so without a limit a runaway
 * script can grow to wasm32's 4 GiB and take the session down. Overruns throw
 * `InternalError: out of memory` inside the script.
 */
const CODEMODE_MEMORY_LIMIT_BYTES = 256 * 1024 * 1024;
// ...
/** Runs at most `limit` calls at once, in call order. */
function createLimiter(limit: number): <T>(run: () => Promise<T>) => Promise<T> {
	let active = 0;
	const waiting: (() => void)[] = [];
	return async (run) => {
		if (active >= limit) await new Promise<void>((resolve) => waiting.push(resolve));
		active++;
		try {
			return await run();
		} finally {
			active--;
			waiting.shift()?.();
		}
	};
}
```

## !!steps A worker queue for the whole process

Each script runs in its own worker thread, and those are limited process-wide, not per session: by default two, which leaves room for one replacement while a cancelled worker is still exiting. Hosts that run many sessions in one process can raise it with `PI_CODEMODE_MAX_WORKERS`, which is read on every call so an SDK host can change it at runtime.

When all slots are taken, `reserveCodemodeWorker` queues the script in arrival order instead of failing it. The wait ends with a slot, an abort, or a timeout. The timeout exists because a deadlock is possible: an in-process subagent's script can wait on another script, and if every worker is held by such a waiter none would ever free up. `settle` always removes the waiter, the timer and the abort listener, so a script that gave up cannot be granted a slot later.

```ts ! execute.ts
// Shared across calls and sessions. Allow one replacement while a cancelled worker is still exiting.
const DEFAULT_MAX_CODEMODE_WORKERS = 2;

/** `PI_CODEMODE_MAX_WORKERS` if it is a positive integer. Read per call so SDK hosts can set it at runtime. */
function maxCodemodeWorkers(): number {
	const value = Number(process.env.PI_CODEMODE_MAX_WORKERS);
	return Number.isInteger(value) && value > 0 ? value : DEFAULT_MAX_CODEMODE_WORKERS;
}
/**
 * How long a script waits for a free worker before failing. Bounds the wait when every worker is
 * held by a script that waits on another script, for example an in-process subagent that uses codemode.
 */
const CODEMODE_WORKER_WAIT_MS = 60_000;
let activeCodemodeWorkers = 0;
/** Scripts waiting for a worker, in arrival order. */
const codemodeWorkerWaiters: (() => void)[] = [];
// ...
	if (signal?.aborted) return Promise.resolve("aborted");
	return new Promise((resolve) => {
		const settle = (outcome: "reserved" | "aborted" | "timeout") => {
			clearTimeout(timer);
			signal?.removeEventListener("abort", onAbort);
			const index = codemodeWorkerWaiters.indexOf(grant);
			if (index >= 0) codemodeWorkerWaiters.splice(index, 1);
			resolve(outcome);
		};
		const grant = () => settle("reserved");
		const onAbort = () => settle("aborted");
		const timer = setTimeout(() => settle("timeout"), timeoutMs);
		codemodeWorkerWaiters.push(grant);
		signal?.addEventListener("abort", onAbort, { once: true });
		admitCodemodeWorkers();
	});
}

/** Give free slots to waiting scripts in arrival order. */
function admitCodemodeWorkers(): void {
	while (codemodeWorkerWaiters.length > 0 && activeCodemodeWorkers < maxCodemodeWorkers()) {
		activeCodemodeWorkers++;
		codemodeWorkerWaiters.shift()?.();
	}
}

function releaseCodemodeWorker(): void {
	activeCodemodeWorkers--;
	admitCodemodeWorkers();
}
```

## !!steps Validating classifier contexts

Scripts pass plain objects to `models.classify()`. Rather than let a malformed context reach a provider and come back as an obscure error, `checkClassifierContext` validates it and throws with the expected shape and a pointer to the docs. It checks that `state` is an object, that the optional `images` array holds only image blocks (classifiers can now look at images), that `questions` is a non-empty map, and that each question's criteria match its type: choice maps labels to meanings, score lists levels lowest first, bool has `true` and `false` strings.

Field access goes through the `ScriptValue` type, an object read field by field where anything that is not an object simply has no fields. `checkImagesContext` does the same for `models.generateImages()`, requiring a non-empty `input` array of text or image blocks.

## !!steps Reading the store from the branch

`store(key, value)` persists across codemode calls through session entries, not a side file. `readCodemodeStore` walks the current branch from the root and applies each `codemode-store` custom entry: deletes first, then sets. Because it reads the branch, forking a session gives each branch the values written on its own path.

`isStoreEntryData` guards against malformed entries instead of trusting the stored data.

```ts ! execute.ts
/** Values of `load()`: the `codemode-store` entries on the branch, applied from the root. */
export function readCodemodeStore(branch: readonly SessionEntry[]): Record<string, unknown> {
	const store = new Map<string, unknown>();
	for (const entry of branch) {
		if (entry.type !== "custom" || entry.customType !== CODEMODE_STORE_ENTRY_TYPE || !isStoreEntryData(entry.data)) {
			continue;
		}
		for (const key of entry.data.delete) store.delete(key);
		for (const [key, value] of Object.entries(entry.data.set)) store.set(key, value);
	}
	return Object.fromEntries(store);
}
```

## !!steps Laying out the output

Providers join adjacent text blocks with a newline or with nothing, so two `text()` calls could run together in what the model sees. `formatOutput` prevents that: when there is more than one text item, each gets a `==> text N/M <==` header line. The sandbox marks `console.*` output with `console: true`, and those lines are collected into a single `console_output` block placed after everything else.

`joinAdjacentText` then merges neighbouring text items into one, putting each part on its own line, while images split the runs. The comment records a performance fix: checking `endsWith` on the growing joined string made V8 flatten the concatenation on every item, which was quadratic, so the separator check looks at the last non-empty part instead.

```ts ! execute.ts
function formatOutput(output: readonly CodemodeOutputItem[]): (TextContent | ImageContent)[] {
	const total = output.filter((item) => item.type === "text" && !item.console).length;
	const items: (TextContent | ImageContent)[] = [];
	const consoleLines: string[] = [];
	let index = 0;
	for (const item of output) {
		if (item.type === "image") {
			items.push(item);
		} else if (item.console) {
			consoleLines.push(item.text);
		} else {
			index++;
			// !mark
			items.push({ type: "text", text: total > 1 ? `==> text ${index}/${total} <==\n${item.text}` : item.text });
		}
	}
	if (consoleLines.length > 0) {
		items.push({ type: "text", text: `<console_output>\n${consoleLines.join("\n")}\n</console_output>` });
	}
	return items;
}
```

## !!steps Errors that keep context

When a script fails, the model gets the script's own stack plus a list of the nested tool calls that already ran, with the explicit warning that they are not undone. That matters because a script may have written files before throwing. Timeouts, aborts and sandbox failures each get their own prefix.

```ts ! execute.ts
function formatCallSummary(calls: readonly CodemodeNestedCall[]): string {
	if (calls.length === 0) return "No tool calls were made.";
	return `Tool calls made before the failure (they are not undone): ${calls.map((call) => `${call.name} (${call.status})`).join(", ")}`;
}

function formatError(result: Extract<CodemodeResult, { ok: false }>, calls: readonly CodemodeNestedCall[]): string {
	const { error } = result;
	const head =
		error.kind === "script"
			? (error.stack ?? `${error.name ?? "Error"}: ${error.message}`)
			: error.kind === "timeout"
				? `Script timed out: ${error.message}`
				: error.kind === "aborted"
					? `Script aborted: ${error.message}`
					: `Script sandbox failed: ${error.message}`;
	return `${head}\n\n${formatCallSummary(calls)}`;
}
```

## !!steps Saving images

The model can see an image returned by `image()`, but it cannot reach the bytes: scripts cannot write files and the `write` tool takes only text. So `saveImages` writes each image to a temp file with [output-files.ts](/docs/src/utils/output-files.ts) and puts a text label with the path in front of the image block.

A write failure becomes part of the label instead of an exception, so a full disk cannot discard the result of a script whose tool calls already ran. Identical images are saved once.

```ts ! execute.ts
	const label = async ({ data, mimeType }: ImageContent): Promise<string> => {
		const bytes = Buffer.from(data, "base64");
		const kind = `${mimeType}, ${formatSize(bytes.length)}`;
		const extension = IMAGE_EXTENSIONS[mimeType];
		if (!extension) throw new Error(`No file extension for image type ${mimeType}`);
		// A failed write (disk full, unwritable temp dir) must not discard the result of a script whose
		// tool calls already ran, so it becomes part of the label.
		try {
			const path = await writeOutputFile("pi-codemode", extension, bytes);
			return `[Image saved to ${path} (${kind})]`;
		} catch (error) {
			return `[Image (${kind}) could not be saved: ${error instanceof Error ? error.message : String(error)}]`;
		}
	};
```

## !!steps Truncating output to a token budget

Output is limited to 10,000 estimated tokens by default (four characters per token); a script can change it with the `max_output_tokens` option. When the combined text is over budget, `truncateOutput` keeps half the budget from the start and half from the end, inserts a count of removed tokens, and writes the full text to a temp file whose path is appended. Images are kept and moved after the text.

The cuts use `sliceHead` and `sliceTail` from [truncate.ts](/docs/src/core/tools/truncate.ts) rather than plain `slice`, so a cut never lands between the two halves of a surrogate pair and leaves invalid UTF-16 in the result. The same helper shortens argument and error previews. This mirrors how bash output is spilled to a file, and the path goes into `details.fullOutputPath` for the renderer.

```ts ! execute.ts
	const texts = items.filter((item): item is TextContent => item.type === "text").map((item) => item.text);
	const combined = texts.join("\n");
	const budget = maxTokens * CHARS_PER_TOKEN;
	if (texts.length === 0 || combined.length <= budget) return { items };
	const headChars = Math.floor(budget / 2);
	const tailChars = budget - headChars;
	const removed = combined.length - headChars - tailChars;
	// !mark(1:2)
	const head = sliceHead(combined, headChars);
	const tail = sliceTail(combined, tailChars);
	let text = `Warning: truncated output (original token count: ${Math.ceil(combined.length / CHARS_PER_TOKEN)})\nTotal output lines: ${combined.split("\n").length}\n\n${head}…${Math.ceil(removed / CHARS_PER_TOKEN)} tokens truncated…${tail}`;
	const spilled = await spillOutput(combined);
```

## !!steps Bridging nested tool calls

An empty update is published before anything else, so the row in [renderer.ts](/docs/src/extensions/codemode/renderer.ts) starts its elapsed-time counter even before the first nested call. Each callable tool then becomes a `CodemodeTool` for the sandbox. When a script calls it, a nested-call record is pushed with status `running` and published through `onUpdate`, which is what the live rows show.

The call itself goes through `ctx.executeTool`, so it passes the same pipeline as a direct call, including hooks and permissions (see also [nested-tool-calls.ts](/docs/src/core/nested-tool-calls.ts)). The record then gets the real tool call id, a duration and a final status, where an aborted signal means `cancelled` rather than `error`. `toScriptValue` decides what the script receives.

```ts ! execute.ts
	const publish = () => onUpdate?.({ content: [], details: snapshot() });
	// Show the script as running before its first nested call, so the row's timer starts.
	// !mark
	publish();
	// ...

			const record: CodemodeNestedCall = {

				status: "running",
			};

			publish();
			const callStartedAt = performance.now();

			if (!ctx) throw new Error("Tool calls need a session");
			const outcome = await ctx.executeTool(tool.name, args, { signal: callSignal });
			record.id = outcome.toolCall.id;
```

## !!steps Waiting for a worker

Before building a sandbox, the script reserves a worker slot. The wait counts toward the script's own `timeout_ms` deadline and is capped at 60 seconds. If no slot arrives, the script never starts, and the result says why in the usual failed-script shape: aborted, timed out against its own deadline, or the 60-second cap was hit with every worker held by other scripts, a message that tells the model to retry later rather than blame its code.

```ts ! execute.ts
	// The wait for a worker counts toward the script's deadline.
	const deadline = sourceOptions.timeoutMs ?? Number.POSITIVE_INFINITY;
	const waitStartedAt = performance.now();
	// !mark
	const admission = await reserveCodemodeWorker(signal, Math.min(deadline, CODEMODE_WORKER_WAIT_MS));
	const waitedMs = performance.now() - waitStartedAt;
	if (admission !== "reserved") {
		const waited = ((performance.now() - startedAt) / 1000).toFixed(1);
		const reason = signal?.reason;
		const error =
			admission === "aborted"
				? `Script aborted: ${reason instanceof Error ? reason.message : "Execution aborted"}`
				: deadline <= CODEMODE_WORKER_WAIT_MS
					? `Script timed out: Execution timed out after ${deadline} ms while waiting for a free codemode worker`
					: `No codemode worker became free within ${CODEMODE_WORKER_WAIT_MS / 1000} seconds. All ${maxCodemodeWorkers()} workers, shared by every session in this process, are held by other scripts. Retry after they finish.`;
		return {
			content: [
				{ type: "text", text: `Script failed\nWall time ${waited} seconds\nOutput:\n` },
				{ type: "text", text: `Script error:\n${error}\n\nThe script did not start.` },
			],
			details: snapshot(),
			isError: true,
		};
	}
```

## !!steps Running the sandbox

The sandbox is created with the nested tools, discovery and model globals, the remaining time after the worker wait (infinite if `// @options:` sets no timeout), the memory cap, the wasm module and the worker specifier from [config.ts](/docs/src/config.ts).

Ownership of the slot is handed over through `acquireWorker`. Until the sandbox starts its worker, this function owns the reservation and the `finally` releases it. Once the sandbox calls `acquireWorker`, the sandbox owns it and calls `releaseCodemodeWorker` only when the worker thread has actually exited, so a cancelled worker that is still shutting down keeps counting against the limit. A launch that resumes after the result has already settled finds `reserved` false and throws instead of starting an unaccounted worker.

Afterwards any call still marked `running` is relabeled `cancelled`: the script ended, timed out or was aborted before it finished.

```ts ! execute.ts
	let reserved = true;

	let sandbox: CodemodeSandbox | undefined;
	let result: CodemodeResult;
	try {
		sandbox = new CodemodeSandbox({
			tools: sandboxTools,
			globals: [
				...createDiscoveryGlobals(callable, samples, options),
				...(options.models && ctx
					? createModelGlobals(ctx.modelRegistry, toolCallId, calls, publish, addModelUsage, addGeneratedImages)
					: []),
			],
			timeoutMs: Math.max(1, Math.round(deadline - waitedMs)),
			memoryLimitBytes: CODEMODE_MEMORY_LIMIT_BYTES,
			wasm: loadQuickJSWasm(getQuickJSWasmPath()),
			workerUrl: getCodemodeWorkerSpecifier(),
			// !mark(1:6)
			acquireWorker: () => {
				if (!reserved) throw new Error("The script already settled");
				// From here the sandbox releases the slot when the worker actually exits.
				reserved = false;
				return releaseCodemodeWorker;
			},
		});
		const store = ctx ? readCodemodeStore(ctx.sessionManager.getBranch()) : {};
		result = await sandbox.execute(code, { signal, store });
	} finally {
		await sandbox?.close();
		// !mark(1:4)
		if (reserved) {
			reserved = false;
			releaseCodemodeWorker();
		}
	}
```

## !!steps Assembling the result

On success, store writes are appended to the session as one `codemode-store` entry, and a returned value is added as one more text item (a pi extension to the script contract), so it gets a header like any `text()` output. The items then go through `formatOutput`, and on failure the error text is appended after whatever partial output exists. If `models.generateImages()` produced images that the script never showed, a note tells the model how to show them.

Adjacent texts are joined before truncation and again after image labels are inserted. The result always starts with a header giving success or failure and wall time, which the renderer strips. Model usage from `models.*` calls is returned as `usage`, and failures set `isError`.

```ts ! execute.ts
	const scriptOutput = [...result.output];
	if (result.ok) {
		const { set, delete: deleted } = result.storeWrites;
		if (Object.keys(set).length > 0 || deleted.length > 0) {
			options.appendEntry?.(CODEMODE_STORE_ENTRY_TYPE, { set, delete: deleted });
		}
		// pi extension: a returned value is appended like text().
		if (result.value !== undefined) scriptOutput.push({ type: "text", text: valueText(result.value) });
	}
	// !mark(1:2)
	const items = formatOutput(scriptOutput);
	if (!result.ok) items.push({ type: "text", text: `Script error:\n${formatError(result, calls)}` });
	// ...
	const truncated = await truncateOutput(
		joinAdjacentText(items),
		sourceOptions.maxOutputTokens ?? DEFAULT_MAX_OUTPUT_TOKENS,
	);
	// After truncation, which joins the text items and moves images after them, so each path stays
	// next to its image and is never cut.
	const output = joinAdjacentText(await saveImages(truncated.items));
```

`searchTools`, `describeTool` and `describeNamespace` let a script find tools that were not listed in the description because of the budget or deferred exposure. `searchTools` ranks with the BM25 ranker from [tool-search/tool.ts](/docs/src/extensions/tool-search/tool.ts), validates its limit and optional namespace filter, and returns names plus declaration samples.

## !!steps Model globals and credential safety
