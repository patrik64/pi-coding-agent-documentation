When a tool result is truncated or is binary, pi saves the full content to a file so the model can still read it later. This module is the one choke point that creates those files, so the storage location can change in one place. Today that is the OS temp directory.

Consumers include [output-accumulator.ts](/docs/src/core/tools/output-accumulator.ts) and [bash-executor.ts](/docs/src/core/bash-executor.ts), plus the MCP and codemode extensions.

<Scrollycoding>

## !!steps Why the module exists

The header comment names the three kinds of output: truncated tool text, binary MCP resources, and images from codemode scripts. Centralizing creation is the point of the file.

```ts ! output-files.ts
/**
 * Output files: files pi writes so the model can use output it was not shown in full, such as the
 * full text of truncated tool output, binary MCP resources, and images shown by codemode scripts.
 * Every output file is created here, so where they are stored can change in one place. Today they
 * go to the OS temp directory.
 */
```

## !!steps Private mode and unpredictable names

Output can contain secrets, so files are created with mode `0o600`. Names are `prefix-<16 hex chars>extension`, built from eight random bytes, which makes the path unguessable.

```ts ! output-files.ts
/** Output can carry private data, so only the user may read the files. */
const OUTPUT_FILE_MODE = 0o600;

/** A new, unused path: `<dir>/<prefix>-<random hex><extension>`. `extension` includes the dot. */
function createOutputFilePath(prefix: string, extension: string): string {
	return join(tmpdir(), `${prefix}-${randomBytes(8).toString("hex")}${extension}`);
}
```

## !!steps Exclusive create for whole writes

`writeOutputFile` uses the `wx` flag, which fails if the path exists and never follows a link planted at the path. This guards against another local user pre-creating a symlink in the shared temp directory.

```ts ! output-files.ts
/** Write `data` to a new output file and return its path. */
export async function writeOutputFile(prefix: string, extension: string, data: string | Uint8Array): Promise<string> {
	const path = createOutputFilePath(prefix, extension);
	// `wx` never follows a link someone else placed at the path.
	// !mark
	await writeFile(path, data, { mode: OUTPUT_FILE_MODE, flag: "wx" });
	return path;
}
```

## !!steps Streaming variant

For output that arrives over time, `createOutputFileStream` returns both the path and an open write stream with the same mode and exclusive flag. The caller owns closing the stream.

```ts ! output-files.ts
/** Open a new output file for streamed output. */
export function createOutputFileStream(prefix: string, extension: string): { path: string; stream: WriteStream } {
	const path = createOutputFilePath(prefix, extension);
	return { path, stream: createWriteStream(path, { mode: OUTPUT_FILE_MODE, flags: "wx" }) };
}
```

</Scrollycoding>

Nothing here cleans files up; they rely on the OS temp directory policy. Note the two APIs spell the option differently (`flag` for `writeFile`, `flags` for `createWriteStream`), which is correct for each Node API.
