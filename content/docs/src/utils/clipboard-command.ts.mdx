All clipboard backends that shell out go through `runClipboardCommand`. It wraps `spawn` so that a missing tool, a hung tool or a huge output all produce the same result: `undefined`. An empty buffer means success with no data.

It is shared by [clipboard.ts](/docs/src/utils/clipboard.ts) for text and [clipboard-image.ts](/docs/src/utils/clipboard-image.ts) for images.

<Scrollycoding>

## !!steps Contract and spawning

The doc comment states the contract: `undefined` means failure. The child is spawned with stdin as a pipe, stdout piped only when no input is being written, and stderr ignored. Clipboard writers such as `xclip` can daemonize, so giving them output pipes would keep the parent waiting on them.

```ts ! clipboard-command.ts
/** Undefined means the command failed; an empty buffer is a successful result. */
export function runClipboardCommand(
	command: string,
	args: readonly string[],
	options?: { input?: string; timeoutMs?: number; maxBufferBytes?: number },
): Promise<Buffer | undefined> {
	return new Promise((resolve) => {
		// Clipboard writers can daemonize. Do not give them output pipes to retain.
		const child = spawn(command, args, {
			// !mark
			stdio: ["pipe", options?.input === undefined ? "pipe" : "ignore", "ignore"],
			windowsHide: true,
		});
```

## !!steps Settling exactly once

`finish` is guarded by a `settled` flag and clears the timer. `abort` kills the child with SIGKILL, destroys the streams and resolves `undefined`. The timer defaults to three seconds.

```ts ! clipboard-command.ts
		const chunks: Buffer[] = [];
		let length = 0;
		let settled = false;
		// !mark
		const finish = (result: Buffer | undefined): void => {
			if (settled) return;
			settled = true;
			clearTimeout(timer);
			resolve(result);
		};
		const abort = (): void => {
			child.kill("SIGKILL");
			child.stdout?.destroy();
			child.stdin?.destroy();
			finish(undefined);
		};
		// !mark
		const timer = setTimeout(abort, options?.timeoutMs ?? 3000);
```

## !!steps Collecting output

On `close` the result is the concatenated output if the exit code is zero, otherwise `undefined`. Chunks are counted as they arrive; exceeding `maxBufferBytes` (default 50 MiB) aborts the command.

```ts ! clipboard-command.ts
		child.on("error", () => finish(undefined));
		child.on("close", (code) => {
			// !mark
			if (!settled) finish(code === 0 ? Buffer.concat(chunks, length) : undefined);
		});
		child.stdout?.on("data", (chunk: Buffer) => {
			if (settled) return;
			length += chunk.length;
			// !mark
			if (length > (options?.maxBufferBytes ?? 50 * 1024 * 1024)) abort();
			else chunks.push(chunk);
		});
```

## !!steps Feeding input

stdin errors are swallowed, since a writer may exit before reading everything. `end` writes the optional input and closes the pipe.

```ts ! clipboard-command.ts
		// !mark
		child.stdin?.on("error", () => {}); // A writer may exit before consuming all input.
		child.stdin?.end(options?.input);
	});
}
```

</Scrollycoding>

Callers choose the timeout: one second for listing types, five seconds for real reads and writes. Because failure is just `undefined`, callers can chain fallbacks without try and catch.
