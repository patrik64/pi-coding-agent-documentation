pi checks a small JSON endpoint on pi.dev to learn whether a newer release exists. This file holds the fetch, the response validation, the semver comparison, and a wrapper that never throws so a flaky network cannot disturb startup.

It builds its requests with [management-http.ts](/docs/src/utils/management-http.ts) for retry and timeout and identifies itself using [pi-user-agent.ts](/docs/src/utils/pi-user-agent.ts). Callers are [interactive-mode.ts](/docs/src/modes/interactive/interactive-mode.ts) and [package-manager-cli.ts](/docs/src/package-manager-cli.ts).

<Scrollycoding>

## !!steps Endpoint and result shape

The release is a version plus optional package name and an optional note (for example a message to show next to the update prompt). The default timeout is 10 seconds.

```ts ! version-check.ts
const LATEST_VERSION_URL = "https://pi.dev/api/latest-version";
const DEFAULT_VERSION_CHECK_TIMEOUT_MS = 10000;

export interface LatestPiRelease {
	version: string;
	packageName?: string;
	note?: string;
}
```

## !!steps Making fetch errors readable

Node reports network failures as "fetch failed" and hides errno codes in `cause`, which may itself be an `AggregateError` (Happy Eyeballs with IPv4 and IPv6). `formatVersionCheckError` collects the `code` fields such as `ENOTFOUND` or `ETIMEDOUT`, deduplicates them, and appends them to the message. If no codes exist, it falls back to the first cause's message.

```ts ! version-check.ts
export function formatVersionCheckError(error: unknown): string {
	const rootMessage = error instanceof Error && error.message ? error.message : String(error);
	const cause = error instanceof Error ? error.cause : undefined;
	const causes = cause instanceof AggregateError ? cause.errors : cause === undefined ? [] : [cause];
	const codes = causes
		.map((value) =>
			typeof value === "object" && value !== null && "code" in value && typeof value.code === "string"
				? value.code
				: undefined,
		)
		.filter((code): code is string => code !== undefined);

	if (codes.length > 0) return `${rootMessage} (${[...new Set(codes)].join(", ")})`;
```

## !!steps Version comparison with a safe fallback

Comparison uses `semver`. If either side is not valid semver, `comparePackageVersions` returns `undefined` and `isNewerPackageVersion` falls back to simple inequality of the trimmed strings. That means an unparseable version is treated as "newer" whenever it differs from the current one.

```ts ! version-check.ts
export function comparePackageVersions(leftVersion: string, rightVersion: string): number | undefined {
	const left = valid(leftVersion.trim());
	const right = valid(rightVersion.trim());
	if (!left || !right) {
		return undefined;
	}
	return compare(left, right);
}

export function isNewerPackageVersion(candidateVersion: string, currentVersion: string): boolean {
	const comparison = comparePackageVersions(candidateVersion, currentVersion);
	if (comparison !== undefined) {
		return comparison > 0;
	}
	return candidateVersion.trim() !== currentVersion.trim();
}
```

## !!steps Fetching the release

`PI_OFFLINE` short-circuits to `undefined`. Retries are off unless `retry` is requested, in which case there are two. A non-OK response yields `undefined`, not an error.

```ts ! version-check.ts
export async function getLatestPiRelease(
	currentVersion: string,
	options: { timeoutMs?: number; retry?: boolean } = {},
): Promise<LatestPiRelease | undefined> {
	if (process.env.PI_OFFLINE) return undefined;

	const response = await fetchWithRetry(
		LATEST_VERSION_URL,
		{
			headers: {
				"User-Agent": getPiUserAgent(currentVersion),
				accept: "application/json",
			},
		},
		{
			maxRetries: options.retry ? 2 : 0,
			timeoutMs: options.timeoutMs ?? DEFAULT_VERSION_CHECK_TIMEOUT_MS,
		},
	);
	if (!response.ok) return undefined;
```

## !!steps Validating untrusted JSON

The body is cast to a shape of `unknown` fields and each is checked at runtime. A missing or blank `version` rejects the whole response. `packageName` and `note` are trimmed and dropped if empty or not strings.

```ts ! version-check.ts
	const data = (await response.json()) as {
		packageName?: unknown;
		version?: unknown;
		note?: unknown;
	};
	if (typeof data.version !== "string" || !data.version.trim()) {
		return undefined;
	}
	const packageName =
		typeof data.packageName === "string" && data.packageName.trim() ? data.packageName.trim() : undefined;
	const note = typeof data.note === "string" && data.note.trim() ? data.note.trim() : undefined;
	return {
		version: data.version.trim(),
		packageName,
		...(note ? { note } : {}),
	};
```

## !!steps The never-throwing startup check

`checkForNewPiVersion` honors `PI_SKIP_VERSION_CHECK`, returns the release only if it is strictly newer, and converts any exception into `undefined`. `getLatestPiVersion` is the version-only convenience used when the caller just needs a string.

```ts ! version-check.ts
export async function checkForNewPiVersion(currentVersion: string): Promise<LatestPiRelease | undefined> {
	if (process.env.PI_SKIP_VERSION_CHECK) return undefined;

	try {
		const latestRelease = await getLatestPiRelease(currentVersion);
		if (latestRelease && isNewerPackageVersion(latestRelease.version, currentVersion)) {
			return latestRelease;
		}
		return undefined;
	} catch {
		return undefined;
	}
}
```

</Scrollycoding>

The split between `getLatestPiRelease` (throws on network errors, which `formatVersionCheckError` is meant to describe) and `checkForNewPiVersion` (silent) lets explicit commands report errors while passive startup checks stay quiet. Offline detection here is any non-empty `PI_OFFLINE`, unlike the stricter parsing in [tools-manager.ts](/docs/src/utils/tools-manager.ts).
