One predicate, `isWSL`, used to decide whether Windows executables are reachable through interop. Clipboard code is the consumer: under WSL it can call Windows tools rather than Linux ones. See [clipboard.ts](/docs/src/utils/clipboard.ts), [clipboard-command.ts](/docs/src/utils/clipboard-command.ts) and [clipboard-image.ts](/docs/src/utils/clipboard-image.ts).

The function takes the environment as a parameter, which keeps it testable without mutating `process.env`.

<Scrollycoding>

## !!steps Cheap environment check first

WSL sets `WSL_DISTRO_NAME` and `WSLENV`. Either one is enough, and the check costs nothing.

```ts ! wsl.ts
/** Windows Subsystem for Linux, where Windows executables are reachable through interop. */
export function isWSL(env: NodeJS.ProcessEnv = process.env): boolean {
	// !mark(1:3)
	if (env.WSL_DISTRO_NAME || env.WSLENV) {
		return true;
	}
```

## !!steps Fall back to the kernel string

If the variables are absent (for example after an env reset or under sudo), it reads `/proc/version` and looks for "microsoft" or "wsl". Any read error, as on macOS or Windows, returns false.

```ts ! wsl.ts
	try {
		const release = readFileSync("/proc/version", "utf-8");
		return /microsoft|wsl/i.test(release);
	} catch {
		return false;
	}
}
```

</Scrollycoding>

The `env` parameter only affects the first check; the `/proc/version` fallback always reads the real file.
