The server's list of sessions is not a database. It is a directory, and each session is a subdirectory that holds a small `meta.json` and a `session.sqlite` file owned by the session's worker. This file reads and writes that layout and nothing else.

The functions are plain async helpers with no class and no cache, so the directory is always the source of truth. The worker side that locks and opens the storage is [session-worker.ts](/docs/src/experimental/session-worker.ts), and the process manager that launches those workers is [session-worker-manager.ts](/docs/src/experimental/session-worker-manager.ts).

## !!steps The metadata shape and file names

`SessionCatalogMetadata` carries the id, creation time, working directory and the session directory path. Note that only `createdAt` and `cwd` are stored in `meta.json`. The id and path are derived from the directory name when reading.

The id pattern starts with an alphanumeric character and allows dots, dashes and underscores up to 128 characters, which rules out path separators and a leading dot, so an id can never escape the catalog directory.

```ts ! session-catalog.ts
/** One server-hosted Session: a directory holding `meta.json` and the worker-owned `session.sqlite`. */
export interface SessionCatalogMetadata {
	readonly id: string;
	readonly createdAt: number;
	/** The working directory the Session's agent runs in. */
	readonly cwd: string;
	/** The Session directory. Workers lock it and own the storage inside it. */
	readonly path: string;
}

const METADATA_FILE = "meta.json";
const STORAGE_FILE = "session.sqlite";
// !mark
const SESSION_ID = /^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$/;

// !mark(1:3)
export function isSessionId(id: string): boolean {
	return SESSION_ID.test(id);
}

/** The durable storage file of a Session. Only the Session's worker opens it. */
export function sessionStoragePath(metadata: SessionCatalogMetadata): string {
	return join(metadata.path, STORAGE_FILE);
}
```

## !!steps Listing is tolerant

A missing session directory is not an error: `listSessions` returns an empty list. Other read errors propagate. Names that do not match the id pattern are ignored, and each remaining name is read in parallel.

Entries that fail to read are dropped from the result.

```ts ! session-catalog.ts
/** Every Session in the directory. Entries without valid metadata are skipped. */
export async function listSessions(sessionDir: string): Promise<SessionCatalogMetadata[]> {
	let names: string[];
	try {
		names = await readdir(sessionDir);
	} catch (error) {
		// !mark
		if (isNotFound(error)) return [];
		throw error;
	}
	// !mark
	const sessions = await Promise.all(names.filter(isSessionId).map((name) => readSession(sessionDir, name)));
	return sessions.filter((metadata) => metadata !== undefined);
}
```

## !!steps Reading one session

`readSession` returns `undefined` for an invalid id, a missing file, unparsable JSON, or fields of the wrong type. It never throws for bad data.

That makes a half-created or hand-edited directory simply invisible instead of breaking the whole server list.

```ts ! session-catalog.ts
/** One Session by ID, or undefined when it does not exist. */
export async function readSession(sessionDir: string, id: string): Promise<SessionCatalogMetadata | undefined> {
	// !mark
	if (!isSessionId(id)) return undefined;
	const path = join(sessionDir, id);
	let value: unknown;
	try {
		value = JSON.parse(await readFile(join(path, METADATA_FILE), "utf8"));
	} catch {
		return undefined;
	}
	if (typeof value !== "object" || value === null) return undefined;
	const { createdAt, cwd } = value as { createdAt?: unknown; cwd?: unknown };
	// !mark
	if (typeof createdAt !== "number" || typeof cwd !== "string") return undefined;
	return { id, createdAt, cwd, path };
}
```

## !!steps Creating a session

The id is the caller's, or a random UUID. The parent directory is created recursively, but the session directory itself is created without `recursive`, so an existing one fails with EEXIST and is reported as already existing. This is what makes id collisions an error and not an overwrite.

`meta.json` is written with tab indentation and a trailing newline.

```ts ! session-catalog.ts
/** Create an empty Session. Its worker creates the storage on first open. */
export async function createSession(
	sessionDir: string,
	options: { readonly id?: string; readonly cwd: string },
): Promise<SessionCatalogMetadata> {
	// !mark
	const id = options.id ?? randomUUID();
	if (!isSessionId(id)) throw new Error(`Invalid session ID: ${id}`);
	const path = join(sessionDir, id);
	await mkdir(sessionDir, { recursive: true });
	try {
		// !mark
		await mkdir(path);
	} catch (error) {
		// !mark
		if ((error as NodeJS.ErrnoException).code === "EEXIST") throw new Error(`Session ${id} already exists`);
		throw error;
	}
	const metadata: SessionCatalogMetadata = { id, createdAt: Date.now(), cwd: options.cwd, path };
	await writeFile(
		join(path, METADATA_FILE),
		`${JSON.stringify({ createdAt: metadata.createdAt, cwd: metadata.cwd }, null, "\t")}\n`,
	);
	return metadata;
}
```

## !!steps Deleting and the storage path

`deleteSession` removes the whole directory with `force`, so a missing directory is not an error. The comment states the precondition that the worker must already be closed. The function does not check it.

`sessionStoragePath` is the only place that names `session.sqlite`, and the doc comment says only the session's worker opens it.

```ts ! session-catalog.ts
/** The durable storage file of a Session. Only the Session's worker opens it. */
export function sessionStoragePath(metadata: SessionCatalogMetadata): string {
	return join(metadata.path, STORAGE_FILE);
}
// ...
/** Delete a Session directory. Its worker must be closed first. */
// !mark(1:3)
export async function deleteSession(metadata: SessionCatalogMetadata): Promise<void> {
	await rm(metadata.path, { recursive: true, force: true });
}

function isNotFound(error: unknown): boolean {
	return (error as NodeJS.ErrnoException | undefined)?.code === "ENOENT";
}
```

</Scrollycoding>

Creation is not atomic: the directory exists before `meta.json` is written, so a crash between the two leaves a directory that `readSession` treats as nonexistent, and a later create with the same id will fail with already exists.
