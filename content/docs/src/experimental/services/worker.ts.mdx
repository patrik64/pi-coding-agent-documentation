This is the composition root of a session worker's services. It gathers the built-in facets (agent controller, plugins runtime, models, transcript), loads plugin facets, starts a facet host, and exposes a single `invoke` entry that the worker uses to answer service calls from the server.

The concerns are lifecycle ones: starting cleanly, reloading plugins without breaking the running host, and disposing everything even when parts fail. The session worker process that calls it is [session-worker.ts](/docs/src/experimental/session-worker.ts).

<Scrollycoding>

## !!steps What a worker runtime and scope are

`SessionWorkerRuntime` bundles the durable harness, the root conversation, and optional model runtime, settings and facet loader. The optional `cleanup` is for things the harness does not own, such as execution environments.

A `WorkerServiceScope` is a server connection id plus an attachment id. It identifies one client's use of the worker, and all subscriptions are keyed by it.

```ts ! worker.ts
export interface SessionWorkerRuntime {
	readonly harness: Harness;
	/** The root conversation the services expose. */
	readonly conversation: Conversation;
	readonly modelRuntime?: ModelRuntime;
	readonly settingsManager?: SettingsManager;
	readonly facetLoader?: FacetLoader;
	// !mark(1:2)
	/** Release resources the Harness does not own, such as execution environments, after it closed. */
	cleanup?(context: Context): Promise<void>;
}

export interface WorkerServiceScope {
	readonly serverConnectionId: string;
	readonly attachmentId: string;
}

interface ScopedServiceEndpoint {
	readonly scope: WorkerServiceScope;
	readonly endpoint: RemoteServiceEndpoint;
}
```

## !!steps The returned surface

`SessionWorkerServices` has three methods. `invoke` runs a service call for a scope. `removeSubscriptions` drops endpoints by predicate, which is how a detached client's subscriptions are cleaned. `dispose` shuts everything down.

`publish` is supplied by the caller and is how updates travel back toward the server, with the scope attached.

```ts ! worker.ts
export interface SessionWorkerServices {
	// !mark(1:2)
	invoke(call: ServiceCall, scope: WorkerServiceScope, context: Context): Promise<JsonValue | undefined>;
	removeSubscriptions(matches: (scope: WorkerServiceScope) => boolean): void;
	dispose(): Promise<void>;
}

export async function createSessionWorkerServices(options: {
	readonly harness: Harness;
	readonly conversation: Conversation;
	readonly modelRuntime: ModelRuntime | undefined;
	readonly settingsManager?: SettingsManager;
	readonly facetLoader?: FacetLoader;
	publish(scope: WorkerServiceScope, subscriptionId: string, update: ServiceProviderUpdate): Promise<void>;
}): Promise<SessionWorkerServices> {
```

## !!steps Built-in facets

Two tiny facets are defined inline. One provides the agent controller from [agent-controller-provider.ts](/docs/src/experimental/services/agent-controller-provider.ts). The other provides `SessionPlugins` and delegates to a mutable `reloadPlugins` function that initially rejects with a not-ready error.

This indirection lets the facet exist before the facet host does, and the real reload is assigned later.

```ts ! worker.ts
	const agentControllerRuntimeFacet = defineFacet({
		id: "@pi/agent-controller-runtime",
		setup(env) {
			env.provide(AgentController, createAgentController(options.harness, options.conversation));
		},
	});
	// !mark
	let reloadPlugins = (): Promise<void> => Promise.reject(new Error("Session plugins are not ready"));
	const pluginRuntimeFacet = defineFacet({
		id: "@pi/session-plugins-runtime",
		setup(env) {
			// !mark
			env.provide(SessionPlugins, { reload: () => reloadPlugins() });
		},
	});
```

## !!steps Loading and startup failure

The built-ins are loaded through a static facet loader, alongside [models-provider.ts](/docs/src/experimental/services/models-provider.ts) and [transcript-provider.ts](/docs/src/experimental/services/transcript-provider.ts). Plugin facets come from the optional loader, defaulting to an empty static loader.

If creating the host throws, both loaded sets are disposed and, when cleanup also fails, everything is reported together in an `AggregateError`. The original error is rethrown otherwise.

```ts ! worker.ts
	const builtins = await createStaticFacetLoader([
		agentControllerRuntimeFacet,
		pluginRuntimeFacet,
		// !mark(1:2)
		await createModelsServiceFacet({ ...options, context: BACKGROUND_CONTEXT }),
		await createTranscriptServiceFacet(options.conversation, BACKGROUND_CONTEXT),
	]).load();
	const pluginLoader = options.facetLoader ?? createStaticFacetLoader([]);
	let loadedPlugins = await pluginLoader.load();
	let facetHost: FacetHost;
	try {
		facetHost = await createFacetHost({ facets: [...builtins.facets, ...loadedPlugins.facets] });
	} catch (error) {
		// !mark
		const cleanup = await Promise.allSettled([loadedPlugins.dispose(), builtins.dispose()]);
		const cleanupErrors = cleanup.flatMap((result) => (result.status === "rejected" ? [result.reason] : []));
		if (cleanupErrors.length > 0) {
			// !mark
			throw new AggregateError([error, ...cleanupErrors], "Session facets failed to start and clean up");
		}
		throw error;
	}
```

## !!steps Serialized plugin reload

`reloadTail` makes reloads run one at a time. Each reload loads a candidate set, asks the host to reload with it, and only on success swaps `loadedPlugins` and disposes the old set. On failure the candidate is disposed and the error is rethrown.

The tail swallows errors, so a failed reload does not stop later ones.

```ts ! worker.ts
	let reloadTail = Promise.resolve();
	reloadPlugins = () => {
		const operation = reloadTail.then(async () => {
			const candidate = await pluginLoader.load();
			try {
				// !mark
				await facetHost.reload(candidate.facets);
			} catch (error) {
				try {
					await candidate.dispose();
				} catch (cleanupError) {
					throw new AggregateError([error, cleanupError], "Session plugin reload and cleanup failed");
				}
				throw error;
			}
			// !mark(1:3)
			const retired = loadedPlugins;
			loadedPlugins = candidate;
			await retired.dispose();
		});
		reloadTail = operation.catch(() => {});
		return operation;
	};
```

## !!steps Endpoints per attachment

Each scope gets its own `RemoteServiceEndpoint` over the host's service provider, created on first use. Subscriptions are held by the endpoint, so disposing it ends them.

`invoke` hands the endpoint a publish callback that forwards to `options.publish` with the scope and subscription id.

```ts ! worker.ts
	const provider = facetHost.services;

	const endpoints = new Map<string, ScopedServiceEndpoint>();
	const removeSubscriptions = (matches: (scope: WorkerServiceScope) => boolean): void => {
		// !mark
		for (const [key, entry] of endpoints) {
			if (!matches(entry.scope)) continue;
			entry.endpoint.dispose();
			endpoints.delete(key);
		}
	};

	return {
		invoke(call, scope, context) {
			const key = serviceScopeKey(scope);
			let entry = endpoints.get(key);
			if (entry === undefined) {
				// !mark
				entry = { scope, endpoint: createRemoteServiceEndpoint(provider) };
				endpoints.set(key, entry);
			}
			return entry.endpoint.invoke(
				call,
				(subscriptionId, update) => options.publish(scope, subscriptionId, update),
				context,
			);
		},
```

## !!steps Disposal collects errors

`dispose` drops all endpoints, waits for the last reload, disposes the host, and then both loaders with `allSettled`. Errors are collected so that no step is skipped because an earlier one failed.

The key helper joins connection and attachment ids with a NUL character, which cannot appear in either.

```ts ! worker.ts
		async dispose() {
			removeSubscriptions(() => true);
			await reloadTail;
			const errors: unknown[] = [];
			try {
				// !mark
				await facetHost.dispose();
			} catch (error) {
				errors.push(error);
			}
			// !mark
			const results = await Promise.allSettled([loadedPlugins.dispose(), builtins.dispose()]);
			errors.push(...results.flatMap((result) => (result.status === "rejected" ? [result.reason] : [])));
			if (errors.length === 1) throw errors[0];
			if (errors.length > 1) throw new AggregateError(errors, "Failed to dispose Session facets");
		},
	};
}

function serviceScopeKey(scope: WorkerServiceScope): string {
	// !mark
	return `${scope.serverConnectionId}\0${scope.attachmentId}`;
}
```

The server side of this protocol is [session-worker-manager.ts](/docs/src/experimental/session-worker-manager.ts), which spawns the worker process, routes service calls to it, and mirrors subscriptions. The `SessionWorkerRuntime.cleanup` hook is declared here, but this file never calls it. The caller is expected to.
