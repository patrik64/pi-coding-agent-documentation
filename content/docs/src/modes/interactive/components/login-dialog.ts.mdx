`LoginDialogComponent` is the visible half of every login flow. The auth backend in pi-ai calls a set of callbacks (`onAuth`, `onDeviceCode`, `onPrompt`, `onProgress`), and each one maps to a `show...` method here that mutates a content area between two borders.

It also owns cancellation. An `AbortController` exposes a `signal` the login flow can pass along, and pending input promises are rejected when the user presses cancel. The provider list that leads here is [oauth-selector.ts](/docs/src/modes/interactive/components/oauth-selector.ts), and [interactive-mode.ts](/docs/src/modes/interactive/interactive-mode.ts) wires the two together.

## !!steps A dialog built from a fixed frame and a swappable body

The constructor lays out a top [dynamic-border.ts](/docs/src/modes/interactive/components/dynamic-border.ts), a title, an empty `contentContainer`, and a bottom border. Everything the login flow shows later goes into `contentContainer`.

The `Input` is created up front but not attached. It is added only when a prompt needs it. Its submit handler resolves the pending promise and swaps itself for a plain `> value` line, so the typed text stays on screen after submission. Escape cancels the whole login.

```ts ! login-dialog.ts
export class LoginDialogComponent extends Container implements Focusable {
	private contentContainer: Container;
	private input: Input;
	private tui: TUI;
	/** The shown sign-in URL, which `app.message.copy` copies. */
	private authUrl?: AuthUrlComponent;
	private abortController = new AbortController();
	private inputResolver?: (value: string) => void;
	private inputRejecter?: (error: Error) => void;
	private onComplete: (success: boolean, message?: string) => void;

// ...
		// Top border
		this.addChild(new DynamicBorder());

		// Title
		this.addChild(new Text(theme.fg("accent", theme.bold(title)), 1, 0));

		// Dynamic content area
		this.contentContainer = new Container();
		this.addChild(this.contentContainer);

		// Input (always present, used when needed)
		this.input = new Input();
		this.input.onSubmit = () => {
			if (this.inputResolver) {
				const value = this.input.getValue();
				this.replaceInputWithSubmittedText(value);
				this.inputResolver(value);
				this.inputResolver = undefined;
				this.inputRejecter = undefined;
			}
		};
		this.input.onEscape = () => {
			this.cancel();
		};

		// Bottom border
		this.addChild(new DynamicBorder());
	}
```

## !!steps Focus forwarding and cancellation

`focused` is a getter and setter that forwards the flag to the inner `Input`. This matters for IME: the terminal cursor must sit in the input to position composition popups.

`cancel` aborts the controller, rejects any waiting prompt with `Login cancelled`, and reports failure through `onComplete`. The dialog never closes itself; the owner decides what to do with the `onComplete` result.

```ts ! login-dialog.ts
	// Focusable implementation - propagate to input for IME cursor positioning
	private _focused = false;
	get focused(): boolean {
		return this._focused;
	}
	set focused(value: boolean) {
		this._focused = value;
		this.input.focused = value;
	}
// ...
	get signal(): AbortSignal {
		return this.abortController.signal;
	}

	private replaceInputWithSubmittedText(value: string): void {
		this.contentContainer.children = this.contentContainer.children.map((child) =>
			child === this.input ? new Text(`> ${value}`, 0, 0) : child,
		);
	}

	private cancel(): void {
		this.abortController.abort();
		if (this.inputRejecter) {
			this.inputRejecter(new Error("Login cancelled"));
			this.inputResolver = undefined;
			this.inputRejecter = undefined;
		}
		this.onComplete(false, "Login cancelled");
	}
```

## !!steps Showing the sign-in URL

`showAuth` clears the body and shows an [auth-url.ts](/docs/src/modes/interactive/components/auth-url.ts) component, plus optional instructions in the warning color. It then calls `openBrowser` from [open-browser.ts](/docs/src/utils/open-browser.ts) so the browser opens without the user copying anything.

The component is kept in `authUrl` so that the copy keybinding can reach it later.

```ts ! login-dialog.ts
	/**
	 * Called by onAuth callback - show URL and optional instructions
	 */
	showAuth(url: string, instructions?: string): void {
		this.contentContainer.clear();
		this.contentContainer.addChild(new Spacer(1));
		this.authUrl = new AuthUrlComponent(this.tui, url);
		this.contentContainer.addChild(this.authUrl);

		if (instructions) {
			this.contentContainer.addChild(new Spacer(1));
			this.contentContainer.addChild(new Text(theme.fg("warning", instructions), 1, 0));
		}

		openBrowser(url);
		this.tui.requestRender();
	}
```

## !!steps Device code flow

For device-code logins the user must open a page and type a code. The URL is wrapped in an OSC 8 escape sequence so supporting terminals make it clickable, and a second dim line gives the platform-specific click hint. `authUrl` is cleared, so the copy shortcut does nothing in this mode.

```ts ! login-dialog.ts
	/**
	 * Called by onDeviceCode callback - show URL and user code.
	 */
	showDeviceCode(info: OAuthDeviceCodeInfo): void {
		this.authUrl = undefined;
		this.contentContainer.clear();
		this.contentContainer.addChild(new Spacer(1));
		const linkedUrl = `\x1b]8;;${info.verificationUri}\x07${info.verificationUri}\x1b]8;;\x07`;
		this.contentContainer.addChild(new Text(theme.fg("accent", linkedUrl), 1, 0));

		const clickHint = process.platform === "darwin" ? "Cmd+click to open" : "Ctrl+click to open";
		const hyperlink = `\x1b]8;;${info.verificationUri}\x07${clickHint}\x1b]8;;\x07`;
		this.contentContainer.addChild(new Text(theme.fg("dim", hyperlink), 1, 0));
		this.contentContainer.addChild(new Spacer(1));
		this.contentContainer.addChild(new Text(theme.fg("warning", `Enter code: ${info.userCode}`), 1, 0));

		this.tui.requestRender();
	}
```

## !!steps Prompts that return promises

`showManualInput` and `showPrompt` attach the shared `Input` and return a promise whose `resolve` and `reject` are stored as fields. The submit handler from the constructor settles them.

Note the difference in clearing: `showPrompt` appends to the existing body so a URL from `showAuth` stays visible, while `showManualInput` does the same without clearing but also resets the value first. Only one input is pending at a time, since the resolver fields are single slots.

```ts ! login-dialog.ts
	/**
	 * Show input for manual code/URL entry (for callback server providers)
	 */
	showManualInput(prompt: string): Promise<string> {
		this.input.setValue("");
		this.contentContainer.addChild(new Spacer(1));
		this.contentContainer.addChild(new Text(theme.fg("dim", prompt), 1, 0));
		this.contentContainer.addChild(this.input);
		this.contentContainer.addChild(new Text(`(${keyHint("tui.select.cancel", "to cancel")})`, 1, 0));
		this.tui.requestRender();

		return new Promise((resolve, reject) => {
			this.inputResolver = resolve;
			this.inputRejecter = reject;
		});
	}
// ...
	/**
	 * Called by onPrompt callback - show prompt and wait for input
	 * Note: Does NOT clear content, appends to existing (preserves URL from showAuth)
	 */
	showPrompt(message: string, placeholder?: string): Promise<string> {
		this.contentContainer.addChild(new Spacer(1));
		this.contentContainer.addChild(new Text(theme.fg("text", message), 1, 0));
		if (placeholder) {
			this.contentContainer.addChild(new Text(theme.fg("dim", `e.g., ${placeholder}`), 1, 0));
		}
		this.contentContainer.addChild(this.input);
		this.contentContainer.addChild(
			new Text(
				`(${keyHint("tui.select.cancel", "to cancel,")} ${keyHint("tui.select.confirm", "to submit")})`,
				1,
				0,
			),
		);

		this.input.setValue("");
		this.tui.requestRender();

		return new Promise((resolve, reject) => {
			this.inputResolver = resolve;
			this.inputRejecter = reject;
		});
	}
```

## !!steps Informational and progress output

`showDetails` replaces the body with plain lines. `showInfo` appends a message and OSC 8 links, with an optional close hint for provider-owned screens that have no callback flow. `showWaiting` and `showProgress` append dim status text for polling flows such as GitHub Copilot.

```ts ! login-dialog.ts
	/** Show informational text before another login step. */
	showDetails(lines: string[]): void {
		this.authUrl = undefined;
		this.contentContainer.clear();
		this.contentContainer.addChild(new Spacer(1));
		for (const line of lines) {
			this.contentContainer.addChild(new Text(line, 1, 0));
		}
		this.tui.requestRender();
	}

	/** Show provider-owned information and links without starting an auth callback flow. */
	showInfo(message: string, links: readonly AuthInfoLink[] = [], showCloseHint = false): void {
		this.contentContainer.addChild(new Spacer(1));
		this.contentContainer.addChild(new Text(theme.fg("text", message), 1, 0));
		for (const link of links) {
			const text = link.label ? `${link.label}: ${link.url}` : link.url;
			const hyperlink = `\x1b]8;;${link.url}\x07${text}\x1b]8;;\x07`;
			this.contentContainer.addChild(new Text(theme.fg("accent", hyperlink), 1, 0));
		}
		if (showCloseHint) {
			this.contentContainer.addChild(new Spacer(1));
			this.contentContainer.addChild(new Text(`(${keyHint("tui.select.cancel", "to close")})`, 1, 0));
		}
		this.tui.requestRender();
	}

	/**
	 * Show waiting message (for polling flows like GitHub Copilot)
	 */
	showWaiting(message: string): void {
		this.contentContainer.addChild(new Spacer(1));
		this.contentContainer.addChild(new Text(theme.fg("dim", message), 1, 0));
		this.contentContainer.addChild(new Text(`(${keyHint("tui.select.cancel", "to cancel")})`, 1, 0));
		this.tui.requestRender();
	}

	/**
	 * Called by onProgress callback
	 */
	showProgress(message: string): void {
		this.contentContainer.addChild(new Text(theme.fg("dim", message), 1, 0));
		this.tui.requestRender();
	}
```

## !!steps Key handling

Cancel is checked first, then the copy shortcut, which only fires when a URL is showing. Everything else goes to the input. Because the `Input` is not a child unless a prompt is active, typing at other times is harmless.

```ts ! login-dialog.ts
	handleInput(data: string): void {
		const kb = getKeybindings();

		if (kb.matches(data, "tui.select.cancel")) {
			this.cancel();
			return;
		}
		if (this.authUrl && kb.matches(data, "app.message.copy")) {
			void this.authUrl.copy();
			return;
		}

		// Pass to input
		this.input.handleInput(data);
	}
```

</Scrollycoding>

The dialog is a passive view: the login orchestration lives elsewhere and calls into it. It leans on [keybinding-hints.ts](/docs/src/modes/interactive/components/keybinding-hints.ts) for hint text. A structural note: appending methods never remove old lines, so long flows accumulate content until a method that clears is called.
