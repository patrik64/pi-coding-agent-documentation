When the user resumes a previous conversation, this is the screen they see. It lists saved sessions, lets them search and switch between the current folder and all folders, and can rename or delete sessions without leaving the picker.

The file holds three cooperating pieces. `SessionSelectorHeader` renders the title, the scope, sort and name indicators, and a context-sensitive hint line. `SessionList` owns the search input, the filtered rows and the keyboard handling. `SessionSelectorComponent` is the exported container that wires them together and runs the asynchronous loading, using loaders that wrap [session-manager.ts](/docs/src/core/session-manager.ts). Filtering and sorting logic lives in [session-selector-search.ts](/docs/src/modes/interactive/components/session-selector-search.ts).

## !!steps Compact relative dates

Rows show the age of a session as a single short token. `formatSessionDate` walks down from "now" through minutes, hours, days, weeks, months and years, and each boundary uses the previous unit's count, so 6 days is `6d` and 7 days becomes `1w`. Months are approximated as 30 days and years as 365.

`shortenPath` replaces a leading home directory with `~`, used for the working directory column in the all-folders view and for the optional path display.

```ts ! session-selector.ts
function formatSessionDate(date: Date): string {
	const now = new Date();
	const diffMs = now.getTime() - date.getTime();
	const diffMins = Math.floor(diffMs / 60000);
	const diffHours = Math.floor(diffMs / 3600000);
	const diffDays = Math.floor(diffMs / 86400000);

	// !mark(1:7)
	if (diffMins < 1) return "now";
	if (diffMins < 60) return `${diffMins}m`;
	if (diffHours < 24) return `${diffHours}h`;
	if (diffDays < 7) return `${diffDays}d`;
	if (diffDays < 30) return `${Math.floor(diffDays / 7)}w`;
	if (diffDays < 365) return `${Math.floor(diffDays / 30)}mo`;
	return `${Math.floor(diffDays / 365)}y`;
}
```

## !!steps Building a session tree from parent paths

Forked sessions record the path of their parent, and threaded mode shows that ancestry. `buildSessionTree` first indexes every session by canonicalized path, then attaches each node to its parent if the parent is in the list, otherwise it becomes a root. A session whose parent was filtered out or lives elsewhere therefore appears at the top level instead of vanishing.

Canonicalizing through [paths.ts](/docs/src/utils/paths.ts) matters because the same file can be spelled differently, for instance through a symlink or relative form. Each node also carries `latestActivity`, the newest modification time in its subtree, and siblings are sorted by it, so a thread with a recent fork floats to the top.

```ts ! session-selector.ts
	const roots: SessionTreeNode[] = [];

	for (const session of sessions) {
		const sessionPath = canonicalizePath(session.path) ?? session.path;
		const node = byPath.get(sessionPath)!;
		const parentPath = canonicalizePath(session.parentSessionPath);

		// !mark(1:5)
		if (parentPath && byPath.has(parentPath)) {
			byPath.get(parentPath)!.children.push(node);
		} else {
			roots.push(node);
		}
	}

	const updateLatestActivity = (node: SessionTreeNode): number => {
		let latestActivity = node.session.modified.getTime();
		for (const child of node.children) {
			latestActivity = Math.max(latestActivity, updateLatestActivity(child));
		}
		node.latestActivity = latestActivity;
		return latestActivity;
	};
```

## !!steps Flattening with drawing information

The terminal list is flat, so `flattenSessionTree` walks the tree depth-first and records for every row its depth, whether it is the last sibling, and an `ancestorContinues` array. Together they are enough to draw the connectors later without looking at the tree again.

A subtlety in the code: the continuation flag for a level is `depth > 0 ? !isLast : false`, so top-level roots never draw a vertical line, only nested ancestors do. Note the rule uses the parent's `isLast` at the time of recursion.

```ts ! session-selector.ts
function flattenSessionTree(roots: SessionTreeNode[]): FlatSessionNode[] {
	const result: FlatSessionNode[] = [];

	const walk = (node: SessionTreeNode, depth: number, ancestorContinues: boolean[], isLast: boolean): void => {
		result.push({ session: node.session, depth, isLast, ancestorContinues });

		for (let i = 0; i < node.children.length; i++) {
			const childIsLast = i === node.children.length - 1;
			// Only show continuation line for non-root ancestors
			// !mark
			const continues = depth > 0 ? !isLast : false;
			walk(node.children[i]!, depth + 1, [...ancestorContinues, continues], childIsLast);
		}
	};
```

## !!steps When the list is a tree and when it is flat

`filterSessions` is called after every keystroke, sort change, filter change and data load. The tree is shown only when the sort mode is `threaded` and the query is empty. Any search text, or the `recent` and `relevance` modes, produces a flat list from `filterAndSortSessions`, with every row at depth 0.

The "named" filter is applied before either path, using `hasSessionName`. The method ends by clamping `selectedIndex` into the new range, so the cursor never points past the end after the list shrinks.

```ts ! session-selector.ts
	private filterSessions(query: string): void {
		const trimmed = query.trim();
		const nameFiltered =
			this.nameFilter === "all" ? this.allSessions : this.allSessions.filter((session) => hasSessionName(session));

		// !mark
		if (this.sortMode === "threaded" && !trimmed) {
			// Threaded mode without search: show tree structure
			const roots = buildSessionTree(nameFiltered);
			this.filteredSessions = flattenSessionTree(roots);
		} else {
			// Other modes or with search: flat list
			const filtered = filterAndSortSessions(nameFiltered, query, this.sortMode, "all");
			this.filteredSessions = filtered.map((session) => ({
				session,
				depth: 0,
				isLast: true,
				ancestorContinues: [],
			}));
		}
		// !mark
		this.selectedIndex = Math.min(this.selectedIndex, Math.max(0, this.filteredSessions.length - 1));
	}
```

## !!steps Keeping the selection stable while sessions stream in

Loading is incremental, so `setSessions` is called repeatedly with growing partial lists. `selectionTouched` records whether the user has pressed any navigation key. If not, new data resets the cursor to the top. If so, the code remembers the selected session's path before replacing the data and looks it up again afterwards, so the cursor follows the same session as rows are inserted above it.

If the remembered session is no longer present, the index is left as `filterSessions` clamped it.

```ts ! session-selector.ts
	setSessions(sessions: SessionInfo[], showCwd: boolean): void {
		// !mark
		const selectedPath = this.selectionTouched ? this.getSelectedSessionPath() : undefined;
		this.allSessions = sessions;
		this.showCwd = showCwd;
		this.filterSessions(this.searchInput.getValue());
		if (!this.selectionTouched) {
			this.selectedIndex = 0;
		} else if (selectedPath) {
			const selectedIndex = this.filteredSessions.findIndex((node) => node.session.path === selectedPath);
			// !mark
			if (selectedIndex >= 0) this.selectedIndex = selectedIndex;
		}
	}
```

## !!steps Input handling and the delete confirmation gate

`handleInput` is ordered so that confirmation wins. While a delete is pending, only confirm and cancel are recognized and every other key is swallowed. After that come the scope, sort, filter, path and rename shortcuts, then navigation, and anything unmatched goes to the search input followed by a refilter.

The non-invasive delete alias is context dependent: it deletes only when the search box is empty, otherwise it is forwarded to the input as a normal Backspace-style edit. Deleting the active session is blocked with an error message.

```ts ! session-selector.ts
		// Ctrl+Backspace: non-invasive convenience alias for delete
		// Only triggers deletion when the query is empty; otherwise it is forwarded to the input
		if (kb.matches(keyData, "app.session.deleteNoninvasive")) {
			// !mark(1:5)
			if (this.searchInput.getValue().length > 0) {
				this.searchInput.handleInput(keyData);
				this.filterSessions(this.searchInput.getValue());
				return;
			}

			this.startDeleteConfirmationForSelectedSession();
			return;
		}

		// !mark
		this.selectionTouched = true;
```

## !!steps Trash first, then permanent delete

`deleteSessionFile` tries the `trash` command line tool first so a deletion is recoverable. A path starting with a dash is passed after `--` so it cannot be read as an option. Success means exit status 0, or the file being gone afterwards, which tolerates tools that report errors after doing the work.

Only if that fails does it call `unlink`. When both fail, the error shows the unlink message with a short hint from trash's stderr, capped at 200 characters. The returned `method` lets the UI say "moved to trash" or "deleted". Note `spawnSync` blocks the event loop while trash runs.


## !!steps Rename mode swaps the whole layout

`SessionSelectorComponent` extends `Container` and rebuilds its children whenever the mode changes. `buildBaseLayout` wraps any content in spacers and two accent borders, with an optional header. Entering rename mode builds a small panel with the input and a hint, hides the header, and routes all keys to the input except cancel.

Rename is guarded: it is ignored when no rename callback was provided, or while the current scope is still loading, since the session metadata may be incomplete. After a successful rename it reloads the list, and `finally` ensures the UI returns to list mode even on failure.

```ts ! session-selector.ts
	private buildBaseLayout(content: Component, options?: { showHeader?: boolean }): void {
		this.clear();
		this.addChild(new Spacer(1));
		this.addChild(new DynamicBorder((s) => theme.fg("accent", s)));
		this.addChild(new Spacer(1));
		// !mark(1:4)
		if (options?.showHeader ?? true) {
			this.addChild(this.header);
			this.addChild(new Spacer(1));
		}
		this.addChild(content);
		this.addChild(new Spacer(1));
		this.addChild(new DynamicBorder((s) => theme.fg("accent", s)));
	}
```

## !!steps Abortable loading per scope

`loadScope` is the most careful method. Each scope has its own `AbortController` field, and its presence doubles as the "loading" flag. The `isActive` closure compares the stored controller with the one this call created, so a result from a superseded or cancelled load is dropped at every await boundary.

Partial results from the progress callback are stored even for the hidden scope, but only pushed to the list and header if that scope is the visible one. Errors clear the scope's cached data and show a status message for four seconds. `toggleScope` reuses cached sessions and only triggers a load when none exist and none is running.

```ts ! session-selector.ts
		const isActive = () => (scope === "current" ? this.currentLoad : this.allLoad) === controller;
		const onProgress: SessionListProgress = (loaded, total, partialSessions) => {
			// !mark
			if (!isActive()) return;
			if (partialSessions) {
				const sessions = [...partialSessions];
				if (scope === "current") {
					this.currentSessions = sessions;
				} else {
					this.allSessions = sessions;
				}
				// !mark
				if (scope === this.scope) this.sessionList.setSessions(sessions, showCwd);
			}
			if (scope !== this.scope) return;
			this.header.setProgress(loaded, total);
			this.requestRender();
		};
```
