The session selector lets users search past sessions by id, name, cwd and the full text of messages. This file contains the logic with no UI: a query parser, a matcher and a filter-and-sort function. Each of those fields is matched on its own, and results are ranked by which kind of field matched: a hit in the session name first, then an exact hit in the id, messages or cwd, then a scattered fuzzy hit in the name or cwd.

It works on `SessionInfo` from [session-manager.ts](/docs/src/core/session-manager.ts) and uses `fuzzyMatch` from pi-tui. The UI that calls it is [session-selector.ts](/docs/src/modes/interactive/components/session-selector.ts).

## !!steps Types

Three sort modes exist and the name filter is either all or only named sessions. A parsed query is either a list of fuzzy and phrase tokens or a single regex. Match scores are lower-is-better.

```ts ! session-selector-search.ts
export type SortMode = "threaded" | "recent" | "relevance";

export type NameFilter = "all" | "named";

export interface ParsedSearchQuery {
	mode: "tokens" | "regex";
	tokens: { kind: "fuzzy" | "phrase"; value: string }[];
	regex: RegExp | null;
	/** If set, parsing failed and we should treat query as non-matching. */
	error?: string;
}

export interface MatchResult {
	matches: boolean;
	/** Lower is better; only meaningful when matches === true */
	score: number;
}
```

## !!steps Match tiers

Earlier versions searched one concatenated string of id, name, messages and cwd, scored by match position. A query could then match scattered letters in a UUID or deep in megabytes of transcript, and a real hit late in a long session was buried by the position penalty. Now each token gets a tier, and the tier is multiplied by a million so it always outweighs the fuzzy score inside it.

```ts ! session-selector-search.ts
/**
 * Match tiers, best first. Each token is scored by the best field it matches; tiers dominate
 * fuzzy scores so an exact hit anywhere beats a scattered subsequence in a short field.
 */
const TIER_NAME = 0; // query text appears in the session name
const TIER_TEXT = 1; // query text appears in the session id, messages, or cwd
const TIER_FUZZY = 2; // query characters appear scattered in the session name or cwd
const TIER_WEIGHT = 1_000_000;
// ...
function tierScore(tier: number, score = 0): number {
	return tier * TIER_WEIGHT + score;
}
```

## !!steps Cached message text

`allMessagesText` holds every user and assistant message of a session and can be megabytes long. Lowercasing it on every keystroke would be wasteful, so the lowercase copy, and lazily the whitespace-normalized copy for phrases, is cached in a `WeakMap` keyed by the `SessionInfo`. The cache entry remembers its source string and is rebuilt if the session's text changes.

```ts ! session-selector-search.ts
interface LowercaseCache {
	source: string;
	lower: string;
	normalized?: string;
}

/**
 * Lowercased message text per session. allMessagesText holds every user/assistant message and
 * can be megabytes, so lowercase it once instead of on every keystroke.
 */
const messageTextCache = new WeakMap<SessionInfo, LowercaseCache>();

function getMessageText(session: SessionInfo): LowercaseCache {
	let cached = messageTextCache.get(session);
	if (!cached || cached.source !== session.allMessagesText) {
		cached = { source: session.allMessagesText, lower: session.allMessagesText.toLowerCase() };
		messageTextCache.set(session, cached);
	}
	return cached;
}

function getNormalizedMessageText(session: SessionInfo): string {
	const cached = getMessageText(session);
	cached.normalized ??= cached.lower.replace(/\s+/g, " ").trim();
	return cached.normalized;
}
```

## !!steps Literal and fuzzy tokens

A plain word is first tried as a case-insensitive substring, field by field in tier order. A name hit is refined by the fuzzy score so tighter name matches rank higher; id, message and cwd hits all score the same. Only if no field contains the word literally does fuzzy matching run, and then only against the name and cwd. Ids and messages are never fuzzy-matched, because scattered letters in them are noise.

```ts ! session-selector-search.ts
/** Exact (case-insensitive) text match. Messages and ids are only matched exactly: scattered matches in them are noise. */
function matchLiteralToken(session: SessionInfo, value: string): number | undefined {
	const name = session.name?.toLowerCase() ?? "";
	if (name.includes(value)) return tierScore(TIER_NAME, fuzzyMatch(value, name).score);
	if (session.id.toLowerCase().includes(value)) return tierScore(TIER_TEXT);
	if (getMessageText(session).lower.includes(value)) return tierScore(TIER_TEXT);
	if (session.cwd.toLowerCase().includes(value)) return tierScore(TIER_TEXT);
	return undefined;
}

function matchFuzzyToken(session: SessionInfo, value: string): number | undefined {
	const literal = matchLiteralToken(session, value.toLowerCase());
	if (literal !== undefined) return literal;

	let best: number | undefined;
	for (const field of [session.name ?? "", session.cwd]) {
		const m = fuzzyMatch(value, field);
		if (m.matches && (best === undefined || m.score < best)) best = m.score;
	}
	return best === undefined ? undefined : tierScore(TIER_FUZZY, best);
}
```

## !!steps Phrases and regex

Phrases follow the same field order as literal tokens but compare whitespace-normalized lowercase text, so a phrase matches across line breaks inside one field. Regexes test the raw fields and know only two tiers: name, or anything else.

```ts ! session-selector-search.ts
function matchPhraseToken(session: SessionInfo, phrase: string): number | undefined {
	const name = normalizeWhitespaceLower(session.name ?? "");
	if (name.includes(phrase)) return tierScore(TIER_NAME, fuzzyMatch(phrase, name).score);
	if (session.id.toLowerCase().includes(phrase)) return tierScore(TIER_TEXT);
	if (getNormalizedMessageText(session).includes(phrase)) return tierScore(TIER_TEXT);
	if (normalizeWhitespaceLower(session.cwd).includes(phrase)) return tierScore(TIER_TEXT);
	return undefined;
}

function matchRegex(session: SessionInfo, regex: RegExp): number | undefined {
	if (session.name && regex.test(session.name)) return tierScore(TIER_NAME);
	if (regex.test(session.id) || regex.test(session.allMessagesText) || regex.test(session.cwd)) {
		return tierScore(TIER_TEXT);
	}
	return undefined;
}
```

## !!steps Parsing regex and empty queries

An empty query matches everything. A query starting with `re:` is a case-insensitive regex; empty or invalid patterns return a parse error instead of throwing.

```ts ! session-selector-search.ts
export function parseSearchQuery(query: string): ParsedSearchQuery {
	const trimmed = query.trim();
	if (!trimmed) {
		return { mode: "tokens", tokens: [], regex: null };
	}

	// Regex mode: re:<pattern>
	if (trimmed.startsWith("re:")) {
		const pattern = trimmed.slice(3).trim();
		if (!pattern) {
			return { mode: "regex", tokens: [], regex: null, error: "Empty regex" };
		}
		try {
			return { mode: "regex", tokens: [], regex: new RegExp(pattern, "i") };
		} catch (err) {
			const msg = err instanceof Error ? err.message : String(err);
			return { mode: "regex", tokens: [], regex: null, error: msg };
		}
	}
```

## !!steps Quoted phrases

Otherwise the query is split on whitespace, but double quotes group words into a phrase token. Plain words are fuzzy tokens.

```ts ! session-selector-search.ts
	// Token mode with quote support.
	// Example: foo "node cve" bar
	const tokens: { kind: "fuzzy" | "phrase"; value: string }[] = [];
	let buf = "";
	let inQuote = false;
	let hadUnclosedQuote = false;

	const flush = (kind: "fuzzy" | "phrase"): void => {
		const v = buf.trim();
		buf = "";
		if (!v) return;
		tokens.push({ kind, value: v });
	};

	for (let i = 0; i < trimmed.length; i++) {
		const ch = trimmed[i]!;
		if (ch === '"') {
			if (inQuote) {
				flush("phrase");
				inQuote = false;
			} else {
				flush("fuzzy");
				inQuote = true;
			}
			continue;
		}

		if (!inQuote && /\s/.test(ch)) {
			flush("fuzzy");
			continue;
		}

		buf += ch;
	}
```

## !!steps Unbalanced quotes

If a quote is never closed, the parser abandons quoting and falls back to simple whitespace splitting, so a stray quote does not hide results.

```ts ! session-selector-search.ts
	if (inQuote) {
		hadUnclosedQuote = true;
	}

	// If quotes were unbalanced, fall back to plain whitespace tokenization.
	if (hadUnclosedQuote) {
		return {
			mode: "tokens",
			tokens: trimmed
				.split(/\s+/)
				.map((t) => t.trim())
				.filter((t) => t.length > 0)
				.map((t) => ({ kind: "fuzzy" as const, value: t })),
			regex: null,
		};
	}

	flush(inQuote ? "phrase" : "fuzzy");

	return { mode: "tokens", tokens, regex: null };
```

## !!steps Scoring a session

Every token must match (AND semantics), and the session's score is the sum of its token scores. Because fields are matched separately, one token can never match across a field boundary, though different tokens may match different fields. A phrase that normalizes to nothing is skipped, and an empty token list matches everything with score zero.

```ts ! session-selector-search.ts
/**
 * Each field is matched separately, so a token never matches across field boundaries.
 * Different tokens may match different fields.
 */
export function matchSession(session: SessionInfo, parsed: ParsedSearchQuery): MatchResult {
	if (parsed.mode === "regex") {
		if (!parsed.regex) {
			return { matches: false, score: 0 };
		}
		const score = matchRegex(session, parsed.regex);
		return score === undefined ? { matches: false, score: 0 } : { matches: true, score };
	}

	let totalScore = 0;

	for (const token of parsed.tokens) {
		let score: number | undefined;
		if (token.kind === "phrase") {
			const phrase = normalizeWhitespaceLower(token.value);
			if (!phrase) continue;
			score = matchPhraseToken(session, phrase);
		} else {
			score = matchFuzzyToken(session, token.value);
		}
		if (score === undefined) return { matches: false, score: 0 };
		totalScore += score;
	}

	return { matches: true, score: totalScore };
}
```

## !!steps Filter and sort

The name filter applies first. A parse error yields no results. `recent` mode only filters and keeps incoming order, while `relevance` sorts by score and breaks ties by newest modified time.

```ts ! session-selector-search.ts
export function filterAndSortSessions(
	sessions: SessionInfo[],
	query: string,
	sortMode: SortMode,
	nameFilter: NameFilter = "all",
): SessionInfo[] {
	const nameFiltered =
		nameFilter === "all" ? sessions : sessions.filter((session) => matchesNameFilter(session, nameFilter));
	const trimmed = query.trim();
	if (!trimmed) return nameFiltered;

	const parsed = parseSearchQuery(query);
	if (parsed.error) return [];

	// Recent mode: filter only, keep incoming order.
	if (sortMode === "recent") {
		const filtered: SessionInfo[] = [];
		for (const s of nameFiltered) {
			const res = matchSession(s, parsed);
			if (res.matches) filtered.push(s);
		}
		return filtered;
	}

	// Relevance mode: sort by score, tie-break by modified desc.
	const scored: { session: SessionInfo; score: number }[] = [];
	for (const s of nameFiltered) {
		const res = matchSession(s, parsed);
		if (!res.matches) continue;
		scored.push({ session: s, score: res.score });
	}

	scored.sort((a, b) => {
		if (a.score !== b.score) return a.score - b.score;
		return b.session.modified.getTime() - a.session.modified.getTime();
	});

	return scored.map((r) => r.session);
}
```

</Scrollycoding>

`threaded` is a valid `SortMode` but this function treats it like relevance, since only `recent` is special-cased; threading is presumably handled by the caller. Since token scores are summed, tiers add up across a multi-word query: a session matching two words in its messages lands in the same million-wide band as one matching one word in its name and the other only as a scattered cwd match, and the fuzzy remainders decide between them.
