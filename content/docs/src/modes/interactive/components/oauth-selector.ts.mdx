`OAuthSelectorComponent` lists authentication providers for `/login` and `/logout`. Despite its name it handles both OAuth and API-key providers, labeled through `AuthSelectorProvider.authType`.

Two exported formatting helpers decide the labels and status suffix, so other menus can show the same text. Choosing an entry hands the provider id and auth type to the caller, which usually opens [login-dialog.ts](/docs/src/modes/interactive/components/login-dialog.ts). The sibling menu with an animated entry is [radius-login-selector.ts](/docs/src/modes/interactive/components/radius-login-selector.ts).

## !!steps The provider shape and labels

A provider has an id, a name, an auth type, and optionally the method and a status check result. `subscription: false` makes an OAuth login read as an account rather than a subscription.

```ts ! oauth-selector.ts
export type AuthSelectorProvider = {
	id: string;
	name: string;
	authType: "oauth" | "api_key";
	method?: ApiKeyAuth | OAuthAuth;
	status?: AuthCheck;
	/**
	 * Whether the provider's OAuth sign-in is backed by a subscription. `false` labels it as an account;
	 * unset keeps the "subscription" label.
	 */
	subscription?: boolean;
};

export function formatAuthSelectorProviderType(
	authType: AuthSelectorProvider["authType"],
	subscription?: boolean,
): string {
	if (authType === "api_key") return "API key";
	return subscription === false ? "account" : "subscription";
}
```

## !!steps Describing configuration status

No status means not configured. If credentials exist but of the other auth type, a warning says which kind is configured. Otherwise a green check is shown; when the source looks like environment variable names (uppercase, comma-separated) it is prefixed with `env:`.

```ts ! oauth-selector.ts
/** Themed suffix describing whether and how a login option is configured, for example " ✓ configured". */
export function formatAuthSelectorProviderStatus(provider: AuthSelectorProvider): string {
	if (!provider.status) return theme.fg("muted", " • not configured");
	if (provider.status.type !== provider.authType) {
		const label = `${formatAuthSelectorProviderType(provider.status.type, provider.subscription)} configured`;
		return theme.fg("muted", " • ") + theme.fg("warning", label);
	}
	if (
		!provider.status.source ||
		provider.status.source === "OAuth" ||
		provider.status.source === "stored credential"
	) {
		return theme.fg("success", " ✓ configured");
	}
	const source = /^[A-Z][A-Z0-9_]*(?:, [A-Z][A-Z0-9_]*)*$/.test(provider.status.source)
		? `env: ${provider.status.source}`
		: provider.status.source;
	return theme.fg("success", ` ✓ ${source}`);
}
```

## !!steps Constructing the dialog

The type labels are only shown when the list mixes auth types. The title depends on the mode. The search input submits the selected provider, and the first filter call does the initial render.

```ts ! oauth-selector.ts
export class OAuthSelectorComponent extends Container implements Focusable {
	private searchInput: Input;

// ...
		this.mode = mode;
		this.allProviders = providers;
		this.filteredProviders = providers;
		this.showAuthTypeLabels = new Set(providers.map((provider) => provider.authType)).size > 1;
		this.onSelectCallback = onSelect;
		this.onCancelCallback = onCancel;

		// Add top border
		this.addChild(new DynamicBorder());
		this.addChild(new Spacer(1));

		// Add title
		const title = mode === "login" ? "Select provider to configure:" : "Select provider to logout:";
		this.addChild(new TruncatedText(theme.fg("accent", theme.bold(title)), 1, 0));
		this.addChild(new Spacer(1));

		this.searchInput = new Input();
		if (initialSearchInput) {
			this.searchInput.setValue(initialSearchInput);
		}
		this.searchInput.onSubmit = () => {
			const selectedProvider = this.filteredProviders[this.selectedIndex];
			if (selectedProvider) {
				this.onSelectCallback(selectedProvider.id, selectedProvider.authType);
			}
		};
		this.addChild(this.searchInput);
		this.addChild(new Spacer(1));

		// Create list container
		this.listContainer = new Container();
		this.addChild(this.listContainer);

		this.addChild(new Spacer(1));

		// Add bottom border
		this.addChild(new DynamicBorder());

		// Initial render
		this.filterProviders(initialSearchInput ?? "");
	}
```

## !!steps Fuzzy filtering

Search matches name, id, auth type and method name. The selected index is clamped, not reset, so it stays put while typing if still valid.

```ts ! oauth-selector.ts
	private filterProviders(query: string): void {
		this.filteredProviders = query
			? fuzzyFilter(
					this.allProviders,
					query,
					(provider) => `${provider.name} ${provider.id} ${provider.authType} ${provider.method?.name ?? ""}`,
				)
			: this.allProviders;
		this.selectedIndex = Math.max(0, Math.min(this.selectedIndex, Math.max(0, this.filteredProviders.length - 1)));
		this.updateList();
	}
```

## !!steps Rendering rows

The list shows 8 rows centered on the selection. Each row combines cursor, name, optional type label and the status suffix, in a `TruncatedText` so long names never wrap. The empty message differs for login, logout and filtered-out cases.

```ts ! oauth-selector.ts
	private updateList(): void {
		this.listContainer.clear();

		const maxVisible = 8;
		const startIndex = Math.max(
			0,
			Math.min(this.selectedIndex - Math.floor(maxVisible / 2), this.filteredProviders.length - maxVisible),
		);
		const endIndex = Math.min(startIndex + maxVisible, this.filteredProviders.length);

		for (let i = startIndex; i < endIndex; i++) {
			const provider = this.filteredProviders[i];
			if (!provider) continue;

			const isSelected = i === this.selectedIndex;

			const statusIndicator = formatAuthSelectorProviderStatus(provider);
			const authTypeLabel = this.showAuthTypeLabels
				? theme.fg("muted", ` [${formatAuthSelectorProviderType(provider.authType, provider.subscription)}]`)
				: "";
			let line = "";
			if (isSelected) {
				const prefix = theme.fg("accent", "→ ");
				const text = theme.fg("accent", provider.name);
				line = prefix + text + authTypeLabel + statusIndicator;
			} else {
				const text = `  ${theme.fg("text", provider.name)}`;
				line = text + authTypeLabel + statusIndicator;
			}

			this.listContainer.addChild(new TruncatedText(line, 1, 0));
		}

		if (startIndex > 0 || endIndex < this.filteredProviders.length) {
			const scrollInfo = theme.fg("muted", `  (${this.selectedIndex + 1}/${this.filteredProviders.length})`);
			this.listContainer.addChild(new TruncatedText(scrollInfo, 1, 0));
		}

		// Show "no providers" if empty
		if (this.filteredProviders.length === 0) {
			const message =
				this.allProviders.length === 0
					? this.mode === "login"
						? "No providers available"
						: "No providers logged in. Use /login first."
					: "No matching providers";
			this.listContainer.addChild(new TruncatedText(theme.fg("muted", `  ${message}`), 1, 0));
		}
```

## !!steps Input handling

Unlike [model-selector.ts](/docs/src/modes/interactive/components/model-selector.ts), up and down do not wrap. Enter selects, cancel calls back, and everything else edits the search.

```ts ! oauth-selector.ts
	handleInput(keyData: string): void {
		const kb = getKeybindings();
		// Up arrow
		if (kb.matches(keyData, "tui.select.up")) {
			if (this.filteredProviders.length === 0) return;
			this.selectedIndex = Math.max(0, this.selectedIndex - 1);
			this.updateList();
		}
		// Down arrow
		else if (kb.matches(keyData, "tui.select.down")) {
			if (this.filteredProviders.length === 0) return;
			this.selectedIndex = Math.min(this.filteredProviders.length - 1, this.selectedIndex + 1);
			this.updateList();
		}
		// Enter
		else if (kb.matches(keyData, "tui.select.confirm")) {
			const selectedProvider = this.filteredProviders[this.selectedIndex];
			if (selectedProvider) {
				this.onSelectCallback(selectedProvider.id, selectedProvider.authType);
			}
		}
		// Escape or Ctrl+C
		else if (kb.matches(keyData, "tui.select.cancel")) {
			this.onCancelCallback();
		}
		// Pass everything else to search input
		else {
			this.searchInput.handleInput(keyData);
			this.filterProviders(this.searchInput.getValue());
		}
	}
```

The status helpers are pure apart from the theme, which makes them easy to reuse. The component never mutates credentials; it only reports a choice.
