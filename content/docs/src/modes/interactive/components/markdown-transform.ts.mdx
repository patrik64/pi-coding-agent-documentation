Extensions can register Markdown transformers that rewrite message text before it is rendered. This tiny file turns a list of them into a single function the Markdown components can call with the current width.

The contract types (`MarkdownTransformer`, `MarkdownTransformContext`) live in [types.ts](/docs/src/core/extensions/types.ts). Each transformer chooses the surfaces it runs on: user, assistant and thinking text by default, and optionally `custom` (custom messages and skill blocks), `summary` (branch and compaction summaries) and `changelog` (the What's New and update notices). That filtering happens in [runner.ts](/docs/src/core/extensions/runner.ts), which wraps each transformer so unlisted types pass through, so this file only ever sees a plain list. The built-in consumer is [mermaid.ts](/docs/src/modes/interactive/components/mermaid.ts).

## !!steps Binding the message context

`createMarkdownTransform` captures what is known when a message is created and returns a function that only needs the markdown and the available width, which are known at render time. The message type is fixed. `messageId` and `timestamp` identify the persisted session entry, so they are set only when a message is rendered from the session file; live messages leave them undefined.

`isStreaming` is a callback rather than a value. Assistant messages reuse their Markdown components while a response streams, so a value captured at creation would still say "streaming" after the stream ends. Reading it on every transform lets a transformer that waits for complete text (as the Mermaid one does) run on the final render.

```ts ! markdown-transform.ts
/** Applies extension Markdown transformers. `isStreaming` is read per transform, so a reused component sees a stream end. */
export function createMarkdownTransform(
	messageType: MarkdownTransformContext["messageType"],
	isStreaming: () => boolean,
	transformers: readonly MarkdownTransformer[],
	messageId?: string,
	timestamp?: string,
): (markdown: string, availableWidth: number) => string {
	return (markdown, availableWidth) =>
		applyMarkdownTransformers(
			markdown,
			{ messageType, isStreaming: isStreaming(), availableWidth, messageId, timestamp },
			transformers,
		);
}
```

## !!steps Running the chain safely

Transformers run in order, each receiving the previous output. A result that is not a string is ignored, and a thrown error is swallowed, so a buggy extension can never break rendering; the text simply passes through unchanged for that step.

```ts ! markdown-transform.ts
function applyMarkdownTransformers(
	markdown: string,
	context: MarkdownTransformContext,
	transformers: readonly MarkdownTransformer[],
): string {
	let transformedMarkdown = markdown;
	for (const transformer of transformers) {
		try {
			const transformed = transformer(transformedMarkdown, context);
			if (typeof transformed === "string") {
				transformedMarkdown = transformed;
			}
		} catch {
			// Keep the current Markdown and continue with the next transformer.
		}
	}
	return transformedMarkdown;
}
```

</Scrollycoding>

Because errors are silently swallowed there is no diagnostic for a failing transformer.
