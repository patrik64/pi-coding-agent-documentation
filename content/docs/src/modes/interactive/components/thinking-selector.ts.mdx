This modal lets the user choose a reasoning level for the current model. It lists only the levels the model supports, marks the current one with a check, and offers fuzzy search over level names and descriptions.

A second action sits beside select: a keybinding that stores the highlighted level as the default rather than only applying it. The same descriptions are repeated in [settings-selector.ts](/docs/src/modes/interactive/components/settings-selector.ts).

<Scrollycoding>

## !!steps Level descriptions

A record maps every `ThinkingLevel` to a text with an approximate token budget. The `Record` type forces the table to cover every level.

```ts ! thinking-selector.ts
const THINKING_SELECT_LIST_LAYOUT: SelectListLayoutOptions = {
	minPrimaryColumnWidth: 12,
	maxPrimaryColumnWidth: 32,
};

// !mark(1:9)
const LEVEL_DESCRIPTIONS: Record<ThinkingLevel, string> = {
	off: "No reasoning",
	minimal: "Very brief reasoning (~1k tokens)",
	low: "Light reasoning (~2k tokens)",
	medium: "Moderate reasoning (~8k tokens)",
	high: "Deep reasoning (~16k tokens)",
	xhigh: "Extra-high reasoning (~32k tokens)",
	max: "Maximum reasoning",
};
```

## !!steps Focus forwarding

The component implements `Focusable` and forwards focus to the search input, so the cursor shows in the right place.

```ts ! thinking-selector.ts
export class ThinkingSelectorComponent extends Container implements Focusable {
	private searchInput: Input;
	private selectList: SelectList;
	private selectListChildIndex: number;
	private allItems: SelectItem[];
	private onSelect: (level: ThinkingLevel) => void;
	private onCancel: () => void;
	private onSelectAsDefault?: (level: ThinkingLevel) => void;
	private _focused = false;

	// !mark(1:8)
	get focused(): boolean {
		return this._focused;
	}

	set focused(value: boolean) {
		this._focused = value;
		this.searchInput.focused = value;
	}
```

## !!steps Items and header

Labels start with a check or two spaces so names align. The default level is annotated in its description. The layout adds a title, a hint about the cycle key, and the search box. Hints come from [keybinding-hints.ts](/docs/src/modes/interactive/components/keybinding-hints.ts).

```ts ! thinking-selector.ts
	constructor(
		currentLevel: ThinkingLevel,
		availableLevels: ThinkingLevel[],
		onSelect: (level: ThinkingLevel) => void,
		onCancel: () => void,
		onSelectAsDefault?: (level: ThinkingLevel) => void,
		defaultThinkingLevel?: ThinkingLevel,
	) {
		super();
		this.onSelect = onSelect;
		this.onCancel = onCancel;
		this.onSelectAsDefault = onSelectAsDefault;

		// !mark(1:6)
		this.allItems = availableLevels.map((level) => ({
			value: level,
			label: `${level === currentLevel ? "✓ " : "  "}${level}`,
			description:
				level === defaultThinkingLevel ? `${LEVEL_DESCRIPTIONS[level]} · default` : LEVEL_DESCRIPTIONS[level],
		}));

		// Add top border
		this.addChild(new DynamicBorder());
		this.addChild(new Spacer(1));
		// !mark(1:3)
		this.addChild(new Text("Thinking Level", 0, 0));
		this.addChild(new Spacer(1));
		this.addChild(new Text(`${keyDisplayText("app.thinking.cycle")} cycles thinking levels in-session`, 0, 0));
		this.addChild(new Spacer(1));

		this.searchInput = new Input();
		this.searchInput.onSubmit = () => this.selectList.handleInput("\r");
		this.addChild(this.searchInput);
		this.addChild(new Spacer(1));
```

## !!steps Building the select list

`buildSelectList` creates a list sized to its items, preselects a value, and wires select and cancel callbacks. It is reused for each filter pass.

```ts ! thinking-selector.ts
	private buildSelectList(items: SelectItem[], preselect?: ThinkingLevel): SelectList {
		// !mark
		const list = new SelectList(items, Math.max(1, items.length), getSelectListTheme(), THINKING_SELECT_LIST_LAYOUT);
		// !mark(1:4)
		const currentIndex = items.findIndex((item) => item.value === preselect);
		if (currentIndex !== -1) {
			list.setSelectedIndex(currentIndex);
		}
		list.onSelect = (item) => this.onSelect(item.value as ThinkingLevel);
		list.onCancel = () => this.onCancel();
		return list;
	}
```

## !!steps Filtering replaces the list

On each keystroke the list is rebuilt from fuzzy results and swapped into `children` at the recorded index. The prior selection is kept if it is still in results.

```ts ! thinking-selector.ts
	private applyFilter(query: string): void {
		// !mark(1:3)
		const filtered = query
			? fuzzyFilter(this.allItems, query, (item) => `${item.value} ${item.description ?? ""}`)
			: this.allItems;
		const selectedValue = this.selectList.getSelectedItem()?.value as ThinkingLevel | undefined;
		const newList = this.buildSelectList(filtered, selectedValue);
		// !mark(1:2)
		this.children[this.selectListChildIndex] = newList;
		this.selectList = newList;
	}
```

## !!steps Input routing

The save key is checked first. Navigation, confirm and cancel keys go to the list. All other keys go to the search input, then the filter is re-applied.

```ts ! thinking-selector.ts
	handleInput(keyData: string): void {
		const kb = getKeybindings();
		// !mark(1:5)
		if (kb.matches(keyData, "app.thinking.save") && this.onSelectAsDefault) {
			const item = this.selectList.getSelectedItem();
			if (item) this.onSelectAsDefault(item.value as ThinkingLevel);
			return;
		}

		// !mark(1:5)
		const isNav =
			kb.matches(keyData, "tui.select.up") ||
			kb.matches(keyData, "tui.select.down") ||
			kb.matches(keyData, "tui.select.confirm") ||
			kb.matches(keyData, "tui.select.cancel");
		if (isNav) {
			this.selectList.handleInput(keyData);
			return;
		}

		// !mark(1:2)
		this.searchInput.handleInput(keyData);
		this.applyFilter(this.searchInput.getValue());
	}
```

The save callback is optional; without it the save key is not special-cased and falls through to the search input. The component is instantiated from [interactive-mode.ts](/docs/src/modes/interactive/interactive-mode.ts). The generic version of this search-and-select pattern is `SelectSubmenu` in [settings-submenu.ts](/docs/src/modes/interactive/components/settings-submenu.ts).
