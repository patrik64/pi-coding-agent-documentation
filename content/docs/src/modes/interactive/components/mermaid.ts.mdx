This file is a `MarkdownTransformer` (see [types.ts](/docs/src/core/extensions/types.ts)) that finds fenced `mermaid` blocks and renders them as terminal art using the `lovely-mermaid` library, which replaced `grok-mermaid`. Diagram rows are re-emitted as Markdown inline code spans, so the normal Markdown renderer preserves their spacing.

Whether it runs depends on the `MermaidRenderingMode` setting from [settings-manager.ts](/docs/src/core/settings-manager.ts). Chaining happens in [markdown-transform.ts](/docs/src/modes/interactive/components/markdown-transform.ts).

## !!steps Detecting Mermaid blocks

The file parses Markdown with a `Marked` lexer rather than regexes. `isMermaid` accepts a `code` token whose first info-string word is `mermaid`, case-insensitively. Because only top-level tokens are scanned, blocks nested in lists or quotes are left alone. The theme option needs only `fg` and `getFgAnsi`, so tests can pass a small stub instead of a full `Theme`.

```ts ! mermaid.ts
const markdownParser = new Marked();

type MermaidTheme = Pick<Theme, "fg" | "getFgAnsi">;

interface MermaidTransformerOptions {
	getMode: () => MermaidRenderingMode;
	theme?: MermaidTheme;
}

function isMermaid(token: Token): token is Token & { type: "code"; text: string; lang?: string } {
	return token.type === "code" && token.lang?.trim().split(/\s+/, 1)[0]?.toLowerCase() === "mermaid";
}
```

## !!steps Smuggling rows through Markdown

Each diagram row becomes a code span so spaces and box characters survive. Empty rows use a non-breaking space because an empty span has no height. The delimiter is one backtick longer than the longest run inside the content, with padding if the content starts or ends with a backtick, following CommonMark.

```ts ! mermaid.ts
function codeSpan(line: string): string {
	// Encode each diagram row as inline code (` ... `) so Markdown preserves its spacing and
	// box-drawing characters. Use a non-breaking space for blank rows because an
	// empty code span has no visible height.
	const content = line || "\u00a0";
// ...
	const longestBacktickRun = Math.max(0, ...Array.from(content.matchAll(/`+/g), (match) => match[0].length));
	const fence = "`".repeat(longestBacktickRun + 1);
	const padding = content.startsWith("`") || content.endsWith("`") ? " " : "";
	return `${fence}${padding}${content}${padding}${fence}`;
}
```

## !!steps Theming and links

`lovely-mermaid` does the ANSI styling itself through `toAnsi`, given an `AnsiTheme` of SGR parameters per role. `foreground` turns a theme color into such a parameter by stripping the leading escape and the trailing `m` from `getFgAnsi`. Borders are muted, edges accent, node text and edge labels use body text, and titles add bold (`1;`) to the accent color.

Diagrams can carry links from Mermaid `click` directives. Wrapping a whole box in an OSC 8 hyperlink would make its borders clickable too, so only spans with the `text` role keep their `href`, and only when the terminal reports hyperlink support. Every other span is copied without the link.

```ts ! mermaid.ts
function themedLines(art: MermaidArt, theme: MermaidTheme): string[] {
	const foreground = (color: ThemeColor) => theme.getFgAnsi(color).slice(2, -1);
	const ansiTheme: AnsiTheme = {
		border: foreground("borderMuted"),
		text: foreground("text"),
		edge: foreground("accent"),
		edgeLabel: foreground("text"),
		title: `1;${foreground("accent")}`,
	};
	const linkLabels = getCapabilities().hyperlinks;
	const displayArt: MermaidArt = {
		...art,
		// Only osc 8 the text, not the whole box.
		styled: art.styled.map((row) =>
			row.map((span) => {
				if (span.href === undefined || (linkLabels && span.role === "text")) return span;
				const unlinked = { ...span };
				delete unlinked.href;
				return unlinked;
			}),
		),
	};
	return toAnsi(displayArt, ansiTheme);
}
```

## !!steps When not to transform

The transformer bails out and returns the markdown unchanged when the mode is `off`, when streaming is in progress unless the mode is `streaming`, or when the surface is anything other than `user`, `assistant` or `summary`. Transformers can now be registered for more surfaces (custom messages, the changelog), so the check is an allow-list: diagrams appear in user and assistant text and in expanded branch and compaction summaries, but not in thinking or other surfaces.

```ts ! mermaid.ts
/** Create a transformer that replaces top-level Mermaid code blocks with Unicode terminal diagrams. */
export function createMermaidMarkdownTransformer(options: MermaidTransformerOptions): MarkdownTransformer {
	return (markdown, context) => {
		const mode = options.getMode();
		// Diagrams render in user and assistant text and in model-written summaries, not in thinking or other surfaces.
		if (
			mode === "off" ||
			(context.messageType !== "user" && context.messageType !== "assistant" && context.messageType !== "summary") ||
			(context.isStreaming && mode !== "streaming")
		) {
			return markdown;
		}
```

## !!steps Per-block fallbacks

Each token is mapped back to text. Non-Mermaid tokens return their `raw`. If rendering fails or the art is wider than the terminal, the original block is kept. Once streaming has finished, warnings from the renderer keep the source block and append a one-line warning, so a half-valid diagram is never silently replaced.

```ts ! mermaid.ts
		return markdownParser
			.lexer(markdown)
			.map((token) => {
				if (!isMermaid(token)) return token.raw;
				const art = render(token.text);
				if (!art || art.width > context.availableWidth) return token.raw;
				if (!context.isStreaming && art.warnings.length > 0) {
					const suffix = art.warnings.length > 1 ? ` (+${art.warnings.length - 1} more)` : "";
					const warning = `Mermaid diagram not rendered: ${art.warnings[0]}${suffix}`;
					const styledWarning = options.theme ? options.theme.fg("warning", warning) : warning;
					return `${token.raw}\n${codeSpan(styledWarning)}  \n`;
				}
				const lines = options.theme ? themedLines(art, options.theme) : art.plain;
				// Markdown hard breaks keep every diagram row on its own line.
				return `${lines.map(codeSpan).join("  \n")}\n`;
			})
			.join("");
	};
}
```

</Scrollycoding>

The result is joined back into one string, so the rest of the pipeline sees ordinary Markdown. The module-level `markdownParser` is shared across calls. The `theme` option is optional; without it the renderer's plain rows are used, which lets the transformer run unstyled in tests or non-TUI contexts.
