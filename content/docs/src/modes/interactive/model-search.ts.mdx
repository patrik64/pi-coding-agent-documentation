Model pickers and the `/model` autocomplete use fuzzy matching over a single string per model. How that string is composed decides which results float to the top. This tiny file centralizes two such recipes, so the different pickers agree, plus a helper that decides whether a model's display name is worth printing next to its id.

`getModelSearchText` is used by autocomplete in [interactive-mode.ts](/docs/src/modes/interactive/interactive-mode.ts) and by [scoped-models-selector.ts](/docs/src/modes/interactive/components/scoped-models-selector.ts); `getModelSelectorSearchText` is used by [model-selector.ts](/docs/src/modes/interactive/components/model-selector.ts). Both selectors use `getDistinctModelName` for their rows.

<Scrollycoding>

## !!steps The minimal model shape

Only an id, a provider and an optional display name are needed, so callers can pass either a full model or a stripped object.

```ts ! model-search.ts
export interface ModelSearchItem {
	id: string;
	provider: string;
	name?: string;
}
```

## !!steps Search text that repeats on purpose

The string contains the id, the provider, the `provider/id` form, and again provider and id, then the name if present. The repetition is intentional: it lets a query such as `anthropic opus` or `anthropic/claude` match in several orders and positions.

```ts ! model-search.ts
export function getModelSearchText(item: ModelSearchItem): string {
	const { id, provider } = item;
	const name = item.name ? ` ${item.name}` : "";
	// !mark
	return `${id} ${provider} ${provider}/${id} ${provider} ${id}${name}`;
}
```

## !!steps Showing a name only when it adds information

Selector rows print the model id. Most display names just restate it ("Claude Sonnet 4.5" for `claude-sonnet-4-5`), which would only add noise, but some carry real information, such as a renamed override that lists routing details. `getDistinctModelName` returns the name only in the second case.

Both strings are lowercased and split into letter and digit words. A name word counts as covered if it is a whole id word or, when longer than one character, appears anywhere in the id with separators removed, which handles names that join or split words differently. Single characters must match a whole id word, so a "3" in the name is not hidden just because the id contains a date like `2603`. (The inline comment's own example, "4" against `mistral-small-2603`, would be uncovered even without that rule, since the id contains no 4.) If every name word is covered, the name is dropped.

```ts ! model-search.ts
const splitModelLabel = (value: string): string[] =>
	value
		.toLowerCase()
		.split(/[^\p{L}\p{N}]+/u)
		.filter(Boolean);

/**
 * Returns the model name when it has words the ID does not, e.g. a renamed override like
 * "MiniMax M3 [rasmus@openrouter, parasail]" for "minimax/minimax-m3". Names that only
 * restate the ID with different casing, separators, or a dropped namespace/version suffix
 * ("Claude Sonnet 4.5 (EU)" for "eu.anthropic.claude-sonnet-4-5-20250929-v1:0") return undefined.
 */
export function getDistinctModelName(item: { id: string; name?: string }): string | undefined {
	const name = item.name?.trim();
	if (!name) return undefined;
	const idWords = splitModelLabel(item.id);
	const idTokens = new Set(idWords);
	const compactId = idWords.join("");
	// Single-character words must match a whole ID token: "4" is not covered by "mistral-small-2603".
	// !mark
	const isCovered = (word: string) => idTokens.has(word) || (word.length > 1 && compactId.includes(word));
	return splitModelLabel(name).every(isCovered) ? undefined : name;
}
```

## !!steps The selector variant drops the leading id

The comment explains the problem: proxy providers such as OpenRouter expose ids like `openrouter/openai/gpt-5`. If the bare id led the text, a query for `openai/gpt-5` would rank those proxy entries ahead of the real provider. Starting the string with the provider keeps exact provider-prefixed queries first.

```ts ! model-search.ts
/**
 * The /model selector search should rank exact provider-prefixed queries before proxy-provider IDs
 * like openrouter/openai/gpt-5, so keep the bare model ID out of the leading position.
 */
export function getModelSelectorSearchText(item: ModelSearchItem): string {
	const { id, provider } = item;
	const name = item.name ? ` ${item.name}` : "";
	// !mark
	return `${provider} ${provider}/${id} ${provider} ${id}${name}`;
}
```

</Scrollycoding>

The two functions differ only in the leading `id `. Nothing here tests ranking; the behavior depends entirely on the fuzzy matcher in pi-tui, so changing either string should be checked against that matcher.
