Some terminals implement the Program Status Protocol (OSC 7501): a program
tells the terminal whether it is idle, working, blocked on the user, done or
failed, and the terminal can show that in a tab or send a notification. For an
agent that runs for minutes in a background tab, the useful moments are "it
needs an answer" and "it finished". The encoding lives in pi-tui: its
`Terminal.setProgramStatus` writes the escape sequence only after the terminal
answered the support query (or `PI_PROGRAM_STATUS=1` forces it), and clears the
status when the TUI stops. This file decides *what* to report.

`ProgramStatusReporter` is owned by [interactive-mode.ts](/docs/src/modes/interactive/interactive-mode.ts),
which feeds it every [AgentSession](/docs/src/core/agent-session.ts) event and
calls `setBlocked` for extension dialogs, extension overlays opened with the
`blocked` option of `ctx.ui.custom` (see [types.ts](/docs/src/core/extensions/types.ts)),
and provider logins. It is deliberately conservative about content: messages
carry only the session name, dialog titles and the first line of an error,
never prompts or model output.

## !!steps What can be reported

A blocked status names what pi waits for, using the protocol's three kinds:
`permission`, `question` or `auth`, plus a one-line message. Error messages are
cut to their first line because the protocol message is a single line; pi-tui
would otherwise flatten a multi-line provider error, stack details and all,
into one long line. An empty error becomes "Error".

The class keeps run state separate from resting state. `runResult` is the
outcome the current run will report once it settles; `restingStatus` is what to
show between runs. Open dialogs are a map keyed by source, in the order they
opened, so several can be open at once and the newest one is reported.

```ts ! program-status-reporter.ts
export type BlockedStatus = { kind: NonNullable<ProgramStatus["kind"]>; message: string };

function firstLine(text: string | undefined): string {
	return text?.split(/\r?\n/, 1)[0]?.trim() || "Error";
}

/**
 * Reports interactive-mode state to the terminal (OSC 7501): `working` during agent runs and
 * compaction, `blocked` while a dialog waits for the user, then `done`, `error`, or `idle` once the run
 * settles. Messages are limited to the session name, dialog titles, and the first line of errors; prompts
 * and assistant output are never reported.
 */
export class ProgramStatusReporter {
	private readonly getTerminal: () => Terminal;
	private readonly getSessionName: () => string | undefined;
	private runActive = false;
	private compacting = false;
	/** Outcome of the current run, reported once it settles. */
	private runResult: ProgramStatus = { state: "done" };
	/** Status while no run is active. */
	private restingStatus: ProgramStatus = { state: "idle" };
	/** Open dialogs by source, in the order they opened. The most recent one is reported. */
	private readonly blocked = new Map<string, BlockedStatus>();
	private lastReport: string | undefined;
```

## !!steps Deriving the outcome from session events

A run starts optimistic, as `done`. Every assistant `message_end` overwrites
the outcome, so the latest response decides: an error that an automatic retry
then fixes ends as `done`, not `error`.

Compaction is tracked on its own. Inside a run, an aborted compaction makes the
outcome `idle` and a failed one makes it `error`, because a failed recovery
compaction ends the run unless a later response succeeds. Outside a run, an
aborted compaction rests at `idle` and a manual `/compact` rests at `done` or
`error`; any other compaction leaves the resting status alone.

On `agent_settled` the outcome becomes the resting status, except that a run
the user cancelled reports `idle`, since nothing finished. That is why
`agent_settled` carries `aborted`. `session_info_changed` changes no state but
falls through to `report`, because the session name is part of the message.
Every other event returns without reporting.

```ts ! program-status-reporter.ts
	handleEvent(event: AgentSessionEvent): void {
		switch (event.type) {
			case "agent_start":
				this.runActive = true;
				this.runResult = { state: "done" };
				break;
			case "message_end":
				// The latest response decides the outcome, so a retried error is replaced by its successful retry.
				if (event.message.role !== "assistant") return;
				this.runResult =
					event.message.stopReason === "error"
						? { state: "error", message: firstLine(event.message.errorMessage) }
						: { state: "done" };
				break;
			case "compaction_start":
				this.compacting = true;
				break;
			case "compaction_end":
				this.compacting = false;
				if (this.runActive) {
					// A failed recovery compaction ends the run unless a later response succeeds.
					if (event.aborted) this.runResult = { state: "idle" };
					else if (event.errorMessage) this.runResult = { state: "error", message: firstLine(event.errorMessage) };
				} else if (event.aborted) {
					this.restingStatus = { state: "idle" };
				} else if (event.reason === "manual") {
					this.restingStatus = event.errorMessage
						? { state: "error", message: firstLine(event.errorMessage) }
						: { state: "done" };
				}
				break;
			case "agent_settled":
				this.runActive = false;
				this.restingStatus = event.aborted ? { state: "idle" } : this.runResult;
				break;
			case "session_info_changed":
				// The session name is part of working and done reports.
				break;
			default:
				return;
		}
		this.report();
	}
```

## !!steps Blocked sources and session switches

Each caller of `setBlocked` uses its own source string: `extension-dialog` for
the visible dialog in the editor slot, `extension-overlay:N` for each blocking
overlay, and `login` for a provider login. Deleting before setting moves a
reopened source to the end of the map, so it becomes the newest. Passing
`undefined` clears only that source, so closing one overlay leaves another open
question reported.

`reset` is called when interactive mode rebinds to another session. It forgets
the run and resting state, so the new session starts `idle` rather than showing
the previous session's `done` or `error`. Blocked sources are left to their
owners, which clear them as their dialogs are torn down.

```ts ! program-status-reporter.ts
	/** Report `blocked` for a dialog until it is cleared with `undefined`. Reopening a source replaces it. */
	setBlocked(source: string, status: BlockedStatus | undefined): void {
		this.blocked.delete(source);
		if (status) this.blocked.set(source, status);
		this.report();
	}

	/** Forget the previous session's run, for example after switching sessions. */
	reset(): void {
		this.runActive = false;
		this.compacting = false;
		this.runResult = { state: "done" };
		this.restingStatus = { state: "idle" };
		this.report();
	}
```

## !!steps Choosing and deduplicating the report

`currentStatus` applies a fixed priority. A waiting dialog wins over
everything, because needing the user is the most useful thing to signal.
Compaction comes next, with a fixed message. Then `working` while a run is
active, else the resting status. `working` and `done` carry the session name
as their message, so the terminal can say which session is busy or finished.

`report` adds the app name and compares the serialized status with the last one
sent. Many events leave the status unchanged, and without this check each one
would write the same escape sequence again.

```ts ! program-status-reporter.ts
	report(): void {
		const status: ProgramStatus = { ...this.currentStatus(), app: APP_NAME };
		const key = JSON.stringify(status);
		if (key === this.lastReport) return;
		this.lastReport = key;
		this.getTerminal().setProgramStatus(status);
	}

	private currentStatus(): ProgramStatus {
		const blocked = [...this.blocked.values()].at(-1);
		if (blocked) return { state: "blocked", ...blocked };
		if (this.compacting) return { state: "working", message: "Compacting context" };
		const status = this.runActive ? { state: "working" as const } : this.restingStatus;
		if (status.state === "working" || status.state === "done") return { ...status, message: this.getSessionName() };
		return status;
	}
}
```
